## Objective

While an agent runs `cardine run <ID>`, the developer cannot see what the engine is doing.
During a validation the console only shows `Lifecycle progress: validation/evidence
pending`, for as long as the commands run. Task 208 makes the engine write two files per
task under the shared Git directory:

- `<common>/cardine-operations/<ID>.live.log`: Cardine's own lines (`HH:MM:SS cardine:
  run <ID> started`, `… cardine: validation · round 1 · task-tests: <command>`,
  `… exit 0 after 372s`, `… cardine: run finished: step …, outcome …`) and the raw output
  of each command as it arrives. When it passes 8 MiB it is renamed to
  `<ID>.live.log.1` and a new one starts.
- `<common>/cardine-operations/<ID>.live.json`: the last command started, with `task`,
  `kind` (`validation` or `candidate`), `id`, `round`, `command`, `startedAt`, `pid`,
  `exitStatus` and `finishedAt`; `exitStatus` and `finishedAt` are `null` while it runs.

`cardine.lifecycle.live.live_paths(common_dir, task_id)` returns both paths.

This task shows them in the console, so the developer follows a run as if it were a
command in their own shell, and the agent's context does not change: the agent never
reads these files.

After this task:

- the task row and its details show the running command, its round and identifier, the
  time since it started, and the last line of output;
- `o` opens an output view for the selected task that shows the live log and follows it
  as it grows, like a terminal;
- a command whose process is gone while its status has no exit is shown as interrupted,
  not as running.

## Acceptance Criteria

- [ ] `Task` gains the live command: kind, identifier, round, command, start time, exit
  status, and last output line, or nothing when the task has no status file. The
  snapshot reads it from `<ID>.live.json` and the last non-empty line of
  `<ID>.live.log`, reading at most the last 4 KiB of the log. A test in
  `tests/test_console_snapshot.py` checks a running, a finished and an interrupted
  command (a `pid` that no longer exists).
- [ ] Reading the live files adds no Git command to a snapshot: the existing budget in
  `tests/test_command_context.py` passes unedited. Missing, unreadable or malformed live
  files show no live command and never fail the snapshot.
- [ ] While a command runs, the details show a line such as `Running: validation · round 1
  · task-tests · 6m12s` and `Last output: <line>`, and the list row shows the same state
  in short form. An interrupted command shows `Interrupted: …`. A finished command shows
  nothing extra. A test in `tests/test_console_render.py` checks the three cases.
- [ ] `o` opens the output view of the selected task. The view:
  - shows the last lines of the live log that fit the screen, reading at most the last
    256 KiB;
  - rereads the log on every loop iteration when its size or modification time changed,
    independently of the snapshot refresh interval, and starts again from the new file
    when the log was renamed;
  - follows the end while it is at the bottom; scrolling up with `[`, `↑` or the mouse
    wheel stops following, and `End` or `G` resumes it;
  - removes ANSI escape sequences and other control characters, and keeps only the text
    after the last carriage return of a line;
  - returns to the list with `Esc`; `q` still quits.
  A test checks the tail, the follow and scroll behaviour, the reread after growth and
  after rename, and the cleaning of control characters.
- [ ] The help text and the footer list `o`.
- [ ] A task with no live log opens a view that says the task has no run output yet.
- [ ] Only the files under Expected code surface are edited, together with this task's
  own record, handoff, and state.
- [ ] Every source and test file stays below 1,500 lines.
- [ ] **Task validation.** After the implementation commit, `cardine run` measures the
  commands under Validation; record the `task-tests` result line in the handoff.
- [ ] Every command under Validation passes.

## Technical Context

- A process is alive when `os.kill(pid, 0)` raises no `ProcessLookupError`; a
  `PermissionError` means alive.
- The output view lives in `render.py`, with a small reader object that keeps the last
  size and modification time; `entry.py` holds its open, scroll and follow state like
  `detail_open` and `detail_offset`. `o` is not bound yet.
- The console stays read-only: it never writes, truncates or removes the live files.
- The project's standing decisions are in `PROJECT_WORKFLOW.md`, section `Standing
  decisions`.
