## Objective

Keep completed deliveries out of the console's Closing view when their
historical cleanup records still exist. Keep tasks with real landing or
cleanup work visible, including after Git has unregistered a worktree.

## Acceptance Criteria

- [ ] A landed task with a completed cleanup record, no remaining branch,
  registered worktree, or lifecycle file, and an empty cleanup placeholder
  does not appear in Closing merely because the placeholder's filesystem
  device identifier or the accepted receipt authority has changed.
- [ ] The historical observation requires evidence of completion. A task
  with unfinished cleanup effects or ambiguous evidence, such as a replaced
  or reused worktree path, remains visible with its applicable diagnostic.
- [ ] A genuine pending push or cleanup stays visible in the console,
  including an interrupted cleanup after worktree unregistration. Preserve
  the relevant stop or next action and existing Done count semantics.
- [ ] Add regression coverage for a historical device identifier mismatch
  and for a genuinely unfinished cleanup. Console reads do not modify Git,
  task state, cleanup records, or the filesystem being observed.
- [ ] Every command under Validation passes and Cardine records the results.

## Technical Context

The primary checkout reported 57 done tasks and no open tasks. The console
listed 50 done tasks as Closing with CLEANUP_BLOCKED, starting at task 178.
Sampled cleanup records had every effect marked done and empty placeholders
whose recorded identities differed only in the filesystem device identifier.
Older records also carried an authority that had since changed. The console
currently treats a blocked replay preview as evidence that cleanup remains.
Historical display evidence must not relax the checks used to replay or
execute cleanup.

## Out of scope

Console startup performance, filters, layout, and detail panel changes.
Changes to cleanup execution, authorization or receipt contracts, historical
task state, and cleanup records.
