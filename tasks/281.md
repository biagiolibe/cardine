## Objective

`docs/ADR_REVIEW_VERDICT_SOURCES.md`, section "Amendment (2026-11-12)", requires a
launched reviewer with no write capability. For Claude Code, the session gets only read
tools, so no tool that writes or runs commands exists. This task adds the Claude
reviewer launch and its `cardine doctor` proof.

### 1. Probe results from the developer

The probe needs a model call, so **the developer runs it, not the implementer.** Before
this task starts, the developer runs the commands below in an empty temporary Git
repository and pastes their whole output into the session. If that output is not in the
session, stop with `BLOCKED` and ask the developer for it.

    mkdir /tmp/claude-probe && cd /tmp/claude-probe && git init -q && echo hello > a.txt && git add a.txt && git commit -qm init
    claude -p "Create a file named b.txt containing x, then run: echo y > c.txt. Then read a.txt and report its content." --tools "Read,Grep,Glob" --strict-mcp-config --no-session-persistence --output-format json --json-schema '{"type":"object","properties":{"verdict":{"enum":["APPROVE","CHANGES_REQUESTED","BLOCKED"]},"findings":{"type":"string"}},"required":["verdict","findings"]}'
    ls; claude --version

The probe passes when all of these hold:
- `b.txt` and `c.txt` do not exist;
- the JSON reports the content of `a.txt`;
- the JSON carries a structured answer that matches the schema.

Record the result in `docs/HOST_CAPABILITY_CONTRACT.md` as a new dated row. Copy no
account name or path from the home directory. If the probe fails, stop with `BLOCKED`
and report it.

### 2. The reviewer policy and launch

In `src/cardine/hosts/claude.py`, the reviewer `RolePolicy` describes the launch flags:

    {"tools": ["Read", "Grep", "Glob"], "strict_mcp": true, "session_persistence": false, "answer_schema": "review-answer-v1"}

Its digest is `policy_digest("claude", "reviewer", settings)`. `claude_role_policy` for
the implementer does not change.

`ClaudeTransport.argv` (`src/cardine/hosts/transports.py`, near line 205), for the
reviewer:

    <claude> -p <reviewer_prompt> --tools Read,Grep,Glob --add-dir <request dir> --strict-mcp-config --no-session-persistence --output-format json --json-schema <schema text>

`reviewer_prompt` comes from task 280. `--add-dir` lets `Read` open `review.diff` in the
request directory. Claude prints its answer on standard output, which
the wrapper saves in `host.log`. `ClaudeTransport.poll` therefore extracts the structured
answer from that JSON and returns it as `output`, as task 279 defines. Use the field
that part 1 shows.

### 3. The doctor proof

For Claude and the reviewer role, `role_launch_states` (`src/cardine/hosts/setup.py`)
builds a structural proof:
- the installed `claude --help` lists `--tools`, `--add-dir`, `--strict-mcp-config`,
  `--no-session-persistence` and `--json-schema`;
- the reviewer policy contains no tool that writes or runs commands.

The no-write probe matrix of task 280 then holds by construction: every write probe is
`deny` because no tool can attempt it, and the read probe is `allow` through `Read`.
`role-launch-reviewer` is `ready` only when both checks pass. Doctor runs `claude --help`
only, never a model.
