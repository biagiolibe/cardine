## Objective

Task 279 removes `cardine review verdict --request-id`. `cardine run` records a launched
reviewer's verdict, and the developer records a manual one with `--owner`. No agent
session ever records a verdict.

The role permissions in `src/cardine/hosts/permissions.py` still allow one:
- `_cardine_action`, near lines 266 to 274, allows a reviewer's
  `cardine review verdict … --request-id …`;
- the implementer probe `review-submission`, near line 529, uses `--request-id`.

### 1. The decision

In `_cardine_action`, deny every `cardine review verdict` command for both roles, with
the reason "verdicts are recorded by cardine run or by the developer with --owner". The
`--request-id` test goes.

### 2. The probes

Change the implementer probe `review-submission` to
`cardine review verdict 001 APPROVE`, still `deny`. The reviewer matrix from task 280
already denies verdict commands. If it still has a `review-submission` control with
`allow`, remove that control.
