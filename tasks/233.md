## Objective

Tasks 219 and 220 made the engine wait for another task's integration before task work and
during cleanup. One window is left. `run_integration_step` waits for the lease and then
calls `strategy.prepare_candidate`, which runs a few checks and creates the lease
exclusively in `stage_task_integration` (`src/cardine/integration/merge.py`). When another
task creates its lease between the two, `stage_task_integration` raises `LEASE_HELD`, and
the task stops for a developer although nothing needs one.

On 2026-11-09 task 226 stopped this way at 01:58:04, while task 227 was staging. The same
command worked once 227 had landed.

In `run_integration_step` (`src/cardine/lifecycle/engine.py`), replace the call to
`strategy.prepare_candidate(task_id, None, root)` with:

```python
        try:
            strategy.prepare_candidate(task_id, None, root)
        except CardineStop as error:
            if error.code != 'LEASE_HELD' or (lease.exists() and wait_for_lease(locations, seconds=0)):
                raise
            return envelope(task_id, str(root), step='candidate', outcome='waiting',
                action='wait-for-lease', retry_after_seconds=5,
                next_command=command_reference(argv, 'Wait for the competing integration'))
```

`wait_for_lease` with `seconds=0` does not sleep. It returns `False` for another task's
coherent lease, returns `True` for this task's own lease, and raises `LEASE_HELD` for a
lease whose ownership cannot be verified. So the run waits for a coherent competing lease
and for a lease that is already gone, and every other case still stops.

Add this row to `EMITTER_CAUSES` in `src/cardine/stops/causes.py`, because the emitter
inventory counts the code literal, as it did for `_cleanup_wait`:

```python
    ("src/cardine/lifecycle/engine.py", "run_integration_step", "LEASE_HELD"): ("split", "a lease lost to the coherent integration of another task waits for its release; an unverified or own lease stays a stop"),
```
