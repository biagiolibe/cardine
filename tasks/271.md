# Task 271 — Document how to change the project declaration

## Objective

A consumer needed to change `.cardine/project.json` while tasks were queued and one was
open. The procedure was not written anywhere they would look:
- `PROJECT_WORKFLOW.md` says only "A project change affects new tasks only";
- the `cardine-project` skill has no route for it;
- `docs/PROJECT_DECLARATION.md` describes the fields but not how to change them.

The coordinator then gave them a stricter rule than Cardine 0.9.2 needs.

Write the procedure in two places. Where the code states a fact, the text matches it.

### 1. `docs/PROJECT_DECLARATION.md`

Add a section `## Change the declaration` before the paragraph that starts
"`ci` may be `none`". It says:

1. Commit the change on `main` first. `cardine authorize` refuses while the
   declaration in the checkout differs from `main` ("project declaration differs from
   main; commit or restore it first", `src/cardine/lifecycle/authorization.py`).
2. Then the developer runs `cardine authorize --check --project .` and
   `cardine authorize --apply --project .` from their own terminal. Until then every
   task operation stops with "developer reauthorization required"
   (`require_authority`, `src/cardine/lifecycle/receipts.py`).
3. Queued tasks keep their frozen contract. `cardine task contract update <ID>`
   rebuilds the contract from the record and the new declaration. It keeps the
   status, the transitions and the record path, and it adds a `contract_history`
   entry. The `projectDigest` field records provenance only; nothing compares it.
4. Prepared tasks need no action. `authorize --check` lists each one as
   `task-policy: <ID> predates main; cardine run <ID> will merge main`. The next
   `cardine run` merges `main` into the task branch once the work is committed
   (`docs/RUN_COMMANDS.md`, the paragraph on the policy refresh). Their earlier
   receipts stay valid.
5. Advice: letting open tasks land first avoids merging `main` into a task under
   review and repeating its validation.

### 2. `skills/cardine-project/SKILL.md`

Add this route after the `- Doctor:` line:

"- Policy change: a change to `.cardine/project.json` is committed on `main` first;
then ask the developer to run `cardine authorize --check` and `--apply` from their
terminal. Offer `cardine task contract update <ID>` for queued tasks that should use
the new declaration. Never edit `.cardine/receipt-authority.json`. Open tasks need
no action: their next `cardine run` merges `main` once their work is committed."

Do not name `docs/PROJECT_DECLARATION.md` in the skill. `tests/test_template_commands.py`
requires every `docs/<NAME>.md` that a skill names to exist in the shipped templates,
and this guide does not.
