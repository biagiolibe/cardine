# Task 199 — Report a finished cleanup as done after a new authorization

## Objective

A task that has landed turns back into a blocked cleanup as soon as the developer runs
`cardine authorize` again. On 2026-11-08, after two authorizations, the console shows
task 178, whose state on `main` is `done`, as:

```text
178 [CLOSING] Task 178 — Delete the unreachable installation branches (C7a)
  Closure stop: CLEANUP_BLOCKED
  Next action: CLEANUP_BLOCKED: foreign cleanup owner or changed landing inputs
```

Every effect in its intent `.git/cardine-operations/178.cleanup.json` is `done`: the
push, the worktree, the placeholder, the branch, and the lifecycle file. The intent is
kept on purpose, as the landing record, and `cardine run` replays it through
`finish_delivery`, which starts with `_landed` in `src/cardine/integration/cleanup.py`.
`_landed` requires `binding['authority'] == receipts.require_authority(root)`. The
binding holds the authority of the day of the cleanup (`accepted_main` `a995ee3` and
that day's runtime), so any later authorization fails the comparison. The console
calls `observe_run` in `src/cardine/lifecycle/preview.py`, which calls `_landed` too,
and shows the task as closing. `cardine run 178` would answer `blocked`, not `done`.
Every landed task meets this after the next authorization.

Task 198 removes the runtime from new bindings and keeps the accepted `main` across a
runtime update. It does not cover this case: intents written before it still carry a
runtime, and a changed policy still moves the accepted `main`.

With this task, a cleanup whose required effects are all recorded `done`, and whose
result Git still shows, is reported done without an owner or authority check. Git must
show that `main` contains the landed commit; that the branch, the worktree
registration, and the lifecycle file are gone; and that the placeholder is the empty
directory cleanup created. Any other observation keeps the full replay, so a reused
path or a recreated branch is still preserved and refused.

## Technical Context

- The required effects follow `finish_delivery`: worktree, placeholder, branch, and
  lifecycle always; `cleanup_push` when the intent has a `finalDigest` (a delivery);
  `cleanup_remote` when it records a remote task branch.
- The check reads only local Git facts. It never contacts `origin`: the console calls
  it every refresh.
- Task 198 edits `src/cardine/lifecycle/receipts.py`, `authorization.py`, the task
  state schema, and other test modules. This task edits none of them, and its test does
  not depend on how the authority is computed, so the two tasks land in either order.
- After this task lands, task 178 shows as done in the console with no manual change to
  `.git/cardine-operations/`.

## Developer decisions given in advance

The developer records these decisions in the task contract, so that they
hold however the task is launched, including a bare `Proceed with <TASK-ID>`
from the project console (ADR decision 12). None of these situations needs a
new decision from the developer. After fixing a failure, continue with
revalidation in the same turn; do not stop to report the fix.

- A required command that exits non-zero because of a precondition the agent
  can satisfy (command order, an uncommitted worktree, a missing argument):
  satisfy it and run the command again, once.
- A validation failure caused by this task's own changes: fix it and revalidate, at
  most 3 counted attempts. A test that fails once and passes on an identical
  unchanged rerun is intermittent, recorded in the handoff, and does not count.
  Only after 3 counted failures stop and summarize the failures.
- A counted attempt is one run of the whole Validation section on a committed
  implementation that the agent considers complete. Test runs during
  implementation are development, not attempts.
- Before the first clean-clone, run `python3 scripts/check_repository.py` and one
  `python3 scripts/run_tests.py --parallel` with one `--module` flag for
  `test_run_cleanup`, `test_worktree_cleanup`, `test_run_delivery_disposable`, and
  the repository guards: `test_module_inventory`, `test_layout`, the identifier guard
  (the `tests/test_no_*_identifiers.py` module), `test_text_gates`,
  `test_stop_registry`, and `test_command_word`. Repeat `--module`; a comma-separated
  list is refused.
- Let a started clean-clone finish; do not interrupt it. After a failed clean-clone,
  fix, commit, and run `python3 scripts/run_tests.py --parallel --last-failed` and a
  `--module` run for each module the fix touched before the next counted attempt.
- A stop printed by `cardine run` whose code in `capabilities/stop-codes-v1.json` has
  `human_decision: false`: run the command the stop names, once. If it stops again
