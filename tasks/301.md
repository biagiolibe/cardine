## Objective

Spike 294 (`docs/DOCS_SPLIT_PLAN.md`) proposed moving 18 design records to `docs/design/`.
Every old path would have to remain as a compatibility document, because of:
- public links and anchors;
- the changelog and published releases;
- historical task records;
- tests that read the old paths.

`docs/` would keep the same number of files. The developer decided on 2026-11-12 not to
move any file before 1.0. The goal of `docs/ADR_PRODUCT_DIRECTION.md`, decision 2, is
reached instead with an index: a reader finds the user guides first.

### 1. `docs/README.md`

Write an index with three sections. Each entry is a link and one line of at most 15
words saying what the document is for.

- **User guides.** Every file the plan classifies as `user`, plus `TROUBLESHOOTING.md`.
  Order them for a new user: quick start, troubleshooting, run commands, project
  declaration, upgrade, then the rest.
- **Installed in your project.** The `template-copy` files, with one sentence explaining
  that `cardine init` and `cardine upgrade` install them in each project, where the
  project's own copy is the one to read.
- **Design records.** The ADRs, inventories, probes, the benchmark protocol and the
  plans. ADRs come first, newest first.

`assets/` and `examples/` get one line each.

### 2. The README

In the README's "Documentation" section:
- "Using Cardine" keeps its links;
- "Design" links `docs/README.md#design-records` instead of naming single records, and
  keeps the link to `docs/ADR_CARDINE_1_0.md`;
- add one line: "All documentation:" followed by a Markdown link to `docs/README.md`.

### 3. Keep the index complete

Add a rule to `scripts/check_repository.py`: every tracked `docs/*.md` and
`docs/workflows/*.md` file except `docs/README.md` must be linked from `docs/README.md`.
A missing file fails with "docs/<name> is not listed in docs/README.md". Add the test
cases to `tests/test_check_repository.py`.
