## Objective

CI on `main` at `bfdfa46` fails 5 of 2164 tests. The tasks that caused them validated only
the modules they touched. All five are expectations that the tasks made obsolete; none is a
defect in the product. The CI gate cannot be turned on while the suite is red.

### 1. `test_the_repository_check_fails_on_the_first_finding_and_is_read_only`

Module `test_template_commands`. Task 230 made `check_template_commands` read
`DOCUMENT_COMMAND_FILES` from the given root, and the test's temporary repository holds only
`templates/`. After its `shutil.copytree(...)` line, add:

```python
            for name in cr.DOCUMENT_COMMAND_FILES:
                (root / name).parent.mkdir(parents=True, exist_ok=True)
                shutil.copyfile(ROOT / name, root / name)
```

### 2. `test_upgrade_installs_closure_command_policy_for_governed_and_keeps_local_rules` and `..._for_lean_...`

Module `test_cardine_upgrade_lifecycle`. Task 224 deliberately removed the read-only command
rules from the project rules template; `cardine setup` writes the `cardine` rules in the user
registry (`src/cardine/hosts/codex.py`). In `_assert_upgrade_installs_closure_command_policy`
(`tests/synthetic_upgrade_support.py`), delete the assertion on
`'["meridian", "worktree", ["evidence", "closure-status", "advance"]]'`. The next assertion, on
`["git", "mv"]`, already proves that the closure section is installed.

### 3. `test_walkthrough_closes_and_pushes_the_first_task`

Task 228 deliberately replaced `docs/examples/LEAN_DELIVERY_WALKTHROUGH.md` with a pointer to
the README, because the former walkthrough described an earlier lifecycle. The document has
no executable block now, and the module's other two tests only exercise the runner for that
document. Delete `tests/test_lean_walkthrough.py`.

### 4. `test_upgrade_check_reports_retired_text_without_writes_or_exit_change`

Module `test_cardine_upgrade_merge`. The test sets the framework version of its synthetic
fixture to the repository's version. Task 231 changed that version to `0.9.0`, which is below
the fixture's newest migration (`1.4.0`), so `lock` refuses. Replace
`cardine_cli.read_version(ROOT) + "\n"` with `"1.4.0\n"`, and remove `import cardine_cli` if
nothing else in the file uses it.
