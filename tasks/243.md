# Task 243 — Start Cardine onboarding before project configuration

> **ID**: `243`
> **Category**: Feature
> **Priority**: 🟠 P2
> **Estimate**: ~2h
> **Assigned to**: unassigned
> **Session**: Project onboarding, 2026-11-10
> **Origin**: friction

## Objective

Extend the guide from task 242 to the point where a maintainer has a new or
existing Git checkout and wants to start using Cardine. Support both a
natural-language request to an agent and a terminal-only path through the
first verified task landing.

## Acceptance Criteria

- [ ] In a Git checkout without a Cardine declaration, the read-only
  `cardine guide --project .` explains how to choose `init` or `adopt`,
  which inputs to prepare, and how to preview and apply the chosen plan.
  It distinguishes an unsupported or invalid checkout from a checkout
  that simply has not been configured.
- [ ] The Cardine project skill recognizes a request such as "I want to use
  Cardine here" in a checkout without an installed project router. It
  inspects prerequisites, explains and collects maintainer choices,
  previews the appropriate plan, and asks for consent before applying.
  After configuration it continues with the task 242 guide through host
  setup when applicable and the first verified landing.
- [ ] The Quickstart covers both ways to start, including how to get the
  runtime and host skill if missing. It shows how a maintainer can run
  `init` or `adopt`, then use the guide and lifecycle directly from the
  terminal. CLI help makes the guide discoverable from either command.
  Existing init and adopt output contracts remain compatible.
- [ ] Add a short Get started section to the Cardine README. Give terminal
  users `cardine guide --project .` as the starting command, and link both
  paths to the Quickstart. Introduce the agent path with the line
  "In true Cardine fashion, you can delegate the setup, too." Follow it with
  a copyable prompt that works without a preinstalled skill:
  "I want to use Cardine here. Read the Quickstart at
  https://github.com/biagiolibe/cardine/blob/main/docs/QUICKSTART.md and guide
  me from this checkout to the first integrated task." Explain that the
  shorter request is enough when the Cardine project skill is available.
- [ ] Verify the entry point on both a new and an existing Git checkout.
  Run an isolated terminal-only walkthrough from an unconfigured
  checkout to the first verified landing. Verify that the skill routes
  the natural-language request before any project files are installed.
- [ ] The guide keeps the read-only and offline guarantees and text and
  JSON behavior from task 242. An already configured checkout still gets
  its contextual guide.

## Technical Context

Task 242 defines the contextual guide for a configured checkout and points
to it after successful init or adopt. Reuse that guide and its documented
first-task path. Keep bootstrap discovery independent of the generated
project router. Explain which commands require maintainer decisions or
consent, and which can be run in read-only preview.

## Out of scope

Changes to the semantics of init, adopt, authorization, host setup, or
the task lifecycle. Automatic CI provisioning, plugin distribution and
release changes, and console work.
