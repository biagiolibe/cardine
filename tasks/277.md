## Objective

Four update paths still tell the user about the Meridian plugin marketplace. Its name
changed to `cardine` in `.claude-plugin/marketplace.json`, and installation moved to
pipx and `cardine self-update` (`docs/HOW_TO_UPGRADE.md`). A user who follows them runs a
command for a marketplace that no longer exists.

1. `scripts/release.py`, `adopter_steps` near line 791, prints
   `/plugin marketplace add biagiolibe/meridian#v<version>`,
   `/plugin marketplace update meridian`, and a Codex step that checks out a tag in
   `$CARDINE_ROOT`.
2. `scripts/upgrade_project.sh`, near line 232, prints the same Claude Code and Codex
   steps under "Framework updates".
3. `src/cardine/release/update.py`, line 39: `PLUGIN_UPDATE_COMMAND` is
   `/plugin marketplace update meridian`. The `SELF_UPDATE_PLUGIN_CACHE` stop prints it
   as its resume command.
4. `src/cardine/release/update.py`, `plugin_marketplace_ref` and `plugin_ref_report`
   near line 221. `cardine self-check` reads `extraKnownMarketplaces.meridian.source.ref`
   from the Claude settings. A Cardine install has no such entry, so the line is always
   "Plugin ref: unknown (no extraKnownMarketplaces.meridian.source.ref declared)".

### 1. The printed update steps

`adopter_steps` prints:

    Adopter update steps (not run):
      cardine self-update --check --project .
      cardine self-update --apply --project .
      then, in each project: cardine upgrade --check --project .
      Guide: docs/HOW_TO_UPGRADE.md

In `upgrade_project.sh`, the "Framework updates" block prints the two `cardine
self-update` lines with `--project "$PROJECT"`, and drops the Claude Code and Codex
lines. `cardine self-update` aligns the Claude Code plugin itself
(`docs/HOW_TO_UPGRADE.md`).

### 2. The plugin cache stop

`PLUGIN_UPDATE_COMMAND` becomes the commands that `plugin_alignment_commands` in
`src/cardine/hosts/claude.py` uses for a mismatched plugin, joined with ` && `, with
`<version>` as the version:

    claude plugin marketplace remove cardine && claude plugin marketplace add biagiolibe/cardine#v<version> && claude plugin install cardine@cardine

Build the string from `plugin_alignment_commands("mismatch", "<version>")`, so that the
two never drift apart. The stop code, its class and its registry entry do not change.

### 3. The self-check plugin line

`cardine self-check` reports the installed Cardine plugin from
`<claude config dir>/plugins/installed_plugins.json`, entry `cardine@cardine`. This is
the file that `plugin_state_for` in `src/cardine/hosts/claude.py` reads. The Claude
config dir is `CLAUDE_CONFIG_DIR` when it is set, otherwise `~/.claude`, as
`claude_user_settings_path` resolves it today.

The line becomes one of:
- `Plugin: <versions> (latest release)`;
- `Plugin: <versions> (older than latest release <latest>; run cardine self-update --apply)`;
- `Plugin: <versions> (latest release unknown)`;
- `Plugin: not installed`;
- `Plugin: unknown (<reason>)` for an unreadable file.

The report still writes nothing. Remove the reader of `extraKnownMarketplaces.meridian`.
`tests/fixtures/module_split_baseline.json` records `claude_user_settings_path`,
`plugin_marketplace_ref` and `plugin_ref_report`. Update it for any function you remove
or rename.

### 4. The identifier allowance

After part 3, `src/cardine/release/update.py` names no Meridian identifier. Remove its
allowance from `tests/test_no_meridian_identifiers.py`, near line 57. The test fails on a
stale allowance.
