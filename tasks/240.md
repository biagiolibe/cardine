## Objective

`v0.9.0` ships slash commands that run the plugin's own copy of the CLI, which the receipt
authority refuses; task 236 fixed them on `main`. The README tells users to install the
plugin at `v0.9.0`, and Claude Code refreshes an installed plugin only when its version
changes. This task prepares 0.9.1, a CLI-only release. The developer creates and pushes the
tag; this task does not.

Prepare it by hand, as task 231 did for 0.9.0. Do not run `scripts/release.py prepare`: its
preflight requires a migration for any template change, and ADR work item 4 says that no
template change adds a migration before 1.0. The two templates that task 238 deleted,
`templates/single/PROJECT_PLAN.md` and `templates/single/TECH_DESIGN.md`, were never in a
project's `managedFiles`, so upgrading projects see no managed-file change.

1. `VERSION` becomes `0.9.1`; `"version"` in `.claude-plugin/plugin.json` becomes `0.9.1`.
2. Add `releases/0.9.1.json`, using the date of the implementation commit:

   ```json
   {
     "version": "0.9.1",
     "releaseDate": "<YYYY-MM-DD>",
     "gitTag": "v0.9.1",
     "protocolVersion": 2,
     "workflowBaselineVersion": "0.9.0",
     "baselineChanged": false,
     "migrations": []
   }
   ```

3. `git rm` `changelog.d/007.md`, `017.md`, `034.md`, `035.md`, `036.md`, and `115.md`. They
   describe changes that shipped in 0.9.0 or earlier, and no release consumed them. Keep
   `changelog.d/README.md`.
4. In `CHANGELOG.md`:
   - The `### Removed` bullet under `## [Unreleased]` shipped in 0.9.0 (commit `c315ccc`):
     move the subsection, heading and bullet, to the end of the `## [0.9.0]` section, and
     leave `## [Unreleased]` with an empty body.
   - Add this section between `## [Unreleased]` and `## [0.9.0]`:

     ```markdown
     ## [0.9.1] - <YYYY-MM-DD>

     CLI-only release.

     ### Added

     - `cardine doctor --host claude` reports `claude-plugin`: whether the installed Claude
       Code plugin matches the CLI version.

     ### Changed

     - `cardine status --write` regenerates only the queue.
     - `cardine init` and `cardine adopt` no longer create `PROJECT_PLAN.md` or
       `TECH_DESIGN.md`. An existing `PROJECT_PLAN.md` is left as the project's own file.

     ### Fixed

     - The Claude Code slash commands call the installed `cardine` instead of the plugin's own
       copy, which the receipt authority refused.
     - The `cardine-project` skill and the slash commands describe `cardine adopt` instead of
       saying that conversion is unavailable.

     ### Documentation

     - The README shows the status badges, the 0.9 status, CI before landing, and how to
       install the Claude Code plugin.
     ```

5. Replace `v0.9.0` with `v0.9.1` in `README.md` (the status note, the `git clone` line, and
   the `claude plugin marketplace add` line) and in the `git clone` line of
   `docs/QUICKSTART.md`. In the status note, `**Status: 0.9.0, before 1.0.**` becomes
   `**Status: 0.9.1, before 1.0.**`.
6. Rewrite `docs/RELEASING.md` for any 0.9 release, keeping its title:

   ```markdown
   Until 1.0, prepare a release by hand, as task 240 did for 0.9.1. Do not run
   `scripts/release.py prepare`: its preflight requires a migration for any template
   change, and no template change adds a migration before 1.0 (ADR work item 4).

   1. Confirm that no task is in progress.
   2. A task bumps `VERSION` and `.claude-plugin/plugin.json`, adds
      `releases/<VERSION>.json`, writes the `CHANGELOG.md` section, consumes the fragments in
      `changelog.d/`, and replaces the previous tag in `README.md` and `docs/QUICKSTART.md`.
   3. Run `python3 scripts/check_repository.py`.
   4. Confirm that the full suite is green on `main` in CI.
   5. The developer runs `git tag v<VERSION>` and `git push origin v<VERSION>`.
   6. `.github/workflows/release.yml` verifies the tag and publishes the GitHub release.
   7. Update the installed runtime, then run `cardine authorize` in each checkout. Update
      the Claude Code plugin; `cardine doctor --host claude` reports a mismatch.

   PyPI publication and the merge of `release.py` and `prepare_release.py` come with 1.0.
   ```
