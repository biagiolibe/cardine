## Objective

Task 289 adds `src/cardine/shared/terminal.py` and gives `cardine self-update` sections,
color, progress and a next-steps checklist. The installation path still prints bare
text. On a fresh project on 2026-11-12:

- `cardine guide` printed a plain "Next steps:" list and a "References:" list.
- `cardine setup --check` printed `changes on --apply: 9` with nine bare lines, then the
  full diff of every planned configuration file, with no headings, then
  `next: cardine setup --apply` between the list and the diffs.
- `cardine init` (`src/cardine/templates/interactive_init.py`) prints lines such as
  `plan:`, `proposed commit:`, `result:` and `Next:`.

The developer wants installation to read like update: a serious CLI.

### 1. `cardine guide`

In `src/cardine/shared/project_guide.py`:
- a section title with the checkout;
- a "Where you are" line with one status mark;
- "Next steps" as a numbered list, with commands highlighted by `command`;
- "References" last.

### 2. `cardine init`

In `interactive_init.py`, group the output into Plan, Apply and Next steps:
- the confirmation prompts stay where they are and keep their wording;
- writing and committing are numbered steps;
- pushing runs under a spinner;
- an error is a red `error` line followed by the retry command it prints today.

### 3. `cardine setup`

In `print_setup_plan` and the apply report (`src/cardine/hosts/setup.py`, near line 460):

**Summary** first:
- the changes, grouped by target: Claude Code, Codex, this project, Cardine home;
- one line each, with a short path relative to the home or the project.

**Next steps** right after the summary:
- `cardine setup --apply`;
- restart the agent;
- `cardine doctor`.

**Planned file changes** last:
- the existing diffs, unchanged in content;
- with styling, `+` lines green and `-` lines red.

On `--apply`:
- one numbered step per change, with `✓` or `✗`;
- then the result line it prints today;
- then the restart reminder.

### 4. Plain output stays parseable

With styling off, every line that the CLI prints today still appears, word for word,
except the order and headings that parts 1 to 3 change. In particular, keep:
- the `result:` lines;
- the `next:` lines;
- the `Next:` lines;
- the `changes on --apply: <n>` line.

Agents and tests read them. Move them, but do not reword them.

## Technical Context

- **Developer decision** (2026-11-12): installation and update share one terminal style.
- Human-readable output is never stable (`docs/PUBLIC_SURFACE.md`). Part 4 still keeps
  the lines that agents follow, because the agent path in `docs/QUICKSTART.md` runs these
  commands.
- If the terminal helpers of 289 lack something needed here, for example a diff
  colorizer, add it to the caller module, not to `terminal.py`, and say so in the
  handoff.
- During development, run tests with
  `python3 scripts/run_tests.py --parallel --module <name>`.
