## Objective

0.9 is a `v0.9.0` Git tag, installed from a clone (ADR decision 10). The repository still says
it is version 1.4.0, the last Meridian version: `cardine --version` prints it, and the release
ledger holds 23 Meridian records. ADR decision 1 says that Cardine carries no Meridian tags
and restarts its numbering.

This task prepares the version. The developer creates and pushes the tag; this task does not.

The steps:

1. `VERSION` becomes `0.9.0`; `"version"` in `.claude-plugin/plugin.json` becomes `0.9.0`.
2. In `.cardine/manifest.json`, `frameworkVersion` and `workflowBaselineVersion` become
   `0.9.0`. `git mv .cardine/baselines/1.4.0 .cardine/baselines/0.9.0`.
3. `git rm` every `releases/<version>.json`; the Meridian ledger stays in the Meridian
   repository. Add `releases/0.9.0.json`, using the date of the implementation commit:

   ```json
   {
     "version": "0.9.0",
     "releaseDate": "<YYYY-MM-DD>",
     "gitTag": "v0.9.0",
     "protocolVersion": 2,
     "workflowBaselineVersion": "0.9.0",
     "baselineChanged": false,
     "migrations": []
   }
   ```
4. In `capabilities/retired-text-v1.json`, every `retiredIn` becomes `0.9.0`, because the audit
   compares it with the installed version.
5. In `CHANGELOG.md`, the introduction says Cardine instead of Meridian, and a section goes
   before `## [1.4.0]`:

   ```markdown
   ## [0.9.0] - <YYYY-MM-DD>

   CLI-only release. First Cardine tag: the delivery lifecycle runs through `cardine run`.
   ```
6. In `releases/README.md`, the title becomes `# Cardine Release Ledger`.
7. Add `docs/RELEASING.md`, the one maintainer document for releases (ADR work item 12). For
   0.9 it says, in this order: no task in progress; `python3 scripts/check_repository.py`;
   the full suite is green on `main` in CI; the developer runs `git tag v0.9.0` and `git push
   origin v0.9.0`; `.github/workflows/release.yml` verifies the tag and publishes the GitHub
   release; update the installed runtime, then run `cardine authorize` in each checkout. It
   says that PyPI publication and the merge of `release.py` and `prepare_release.py` come
   with 1.0.
