# Task 260 — Name the conversation language in the per-turn briefing

> **ID**: `260`

## Objective

Agents drift away from the project's conversation language during long sessions. Until
2026-11-08 the plugin's shell hook `hooks/queue-briefing.sh` printed the language at
every prompt. Task 118 made the Python briefing print status only, and commit `fdf57ce`
removed the shell hook; once `cardine setup` aligned the plugin (task 252), it no
longer ran. Neither host prints the language now. The routers still ask the agent to
read `LANGUAGE_POLICY.md`, but nothing repeats it after the first turn.
`docs/HOST_CAPABILITY_CONTRACT.md` still names the capability `Queue and language
briefing`.

Make these edits in `src/cardine/hosts/briefing.py`.

### 1. Read the language from the project

Add a function that reads `LANGUAGE_POLICY.md` at the project root, the same root that
`render_briefing` receives. It looks for lines that start with
`**Conversation language:**` followed by a value in backticks, on one line, as
`src/cardine/adopt/plan.py` parses it.

- The file does not exist: no language line.
- Exactly one matching line, and the value is not `[Conversation language]`: the
  language is that value, stripped.
- No matching line, more than one, the placeholder value, or a file that cannot be read
  or decoded: the language is not set.

The function never raises and never writes. It reads only that file. The caller
payload is still ignored: a language written in the prompt never reaches the output.

### 2. Print it first

`render_briefing` prints the language line before every other line, including
`Preset:` and `Status unavailable:`:
- language set: `Conversation language: <value>. Repository text: English.`
- not set: `Conversation language: not set; see LANGUAGE_POLICY.md. Repository text: English.`
- file absent: nothing; the output is exactly as today.

`_status_lines` and `render_status_lines` do not change.
