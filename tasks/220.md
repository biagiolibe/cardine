## Objective

Tasks run in parallel, and only one can integrate at a time. On 2026-11-08 `cardine run
219` stopped during cleanup with `CLEANUP_BLOCKED` and `human_decision: true`, saying
`foreign cleanup owner or changed landing inputs`. Nothing needed a person. Task 211 had
taken the integration lease and staged its merge in the primary checkout after 219's cleanup
had already pushed `main` and removed its worktree. `_landed` in
`src/cardine/integration/cleanup.py` found tracked changes in the primary checkout and
refused. The same command worked once 211 had landed.

Task 219 made `dispatch_run` wait for a competing lease before task work, but not during
cleanup. A wait at the entry of cleanup is not enough either, because the competing
integration can start in the middle of a cleanup.

After this task, a `CLEANUP_BLOCKED` stop raised while a cleanup intent exists and another
task holds a coherent integration lease returns `outcome: waiting`. Once the lease is
released, the same checks run again, so a real problem still stops.

In `src/cardine/lifecycle/engine.py`, the `except CardineStop` branch of `dispatch_run`
becomes:

```python
result = _cleanup_wait(locations, error) or diagnostic_result(locations, error, step=stage)
```

and, next to `_integration_wait`:

```python
def _cleanup_wait(locations, error):
    """A cleanup stop raised while another task integrates is retried after that lease."""
    from cardine.integration.candidate import operation_path, wait_for_lease
    if error.code != 'CLEANUP_BLOCKED' or not operation_path(locations, 'cleanup').exists():
        return None
    try:
        if wait_for_lease(locations, seconds=0):
            return None
    except CardineStop:
        return None
    argv = ['cardine', 'run', locations.task_id, '--project', str(locations.primary)]
    return envelope(locations.task_id, str(locations.primary), step='landing', outcome='waiting',
                    action='wait-for-lease', retry_after_seconds=5,
                    next_command=command_reference(argv, 'Wait for the competing integration'))
```

`wait_for_lease` with `seconds=0` does not sleep. It returns `True` when there is no lease or
the task owns it, returns `False` for another task's coherent lease, and raises `LEASE_HELD`
for a lease whose ownership cannot be verified. Only `False` waits.

Also give tracked changes their own message. In `_landed`, remove the `git status` clause
from the large condition and add, right after the `foreign cleanup owner or changed landing
inputs` failure:

```python
    if git_output(root, 'status', '--porcelain', '--untracked-files=no'):
        _fail(locations, 'the primary checkout has uncommitted tracked changes')
```

The stop code stays `CLEANUP_BLOCKED`.

Add this row to `EMITTER_CAUSES` in `src/cardine/stops/causes.py`, because the emitter
inventory counts the code literal in `_cleanup_wait`:

```python
    ("src/cardine/lifecycle/engine.py", "_cleanup_wait", "CLEANUP_BLOCKED"): ("split", "a cleanup stop raised during the coherent integration of another task waits for its lease; the same checks run again after release"),
```
