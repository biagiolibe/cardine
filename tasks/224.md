## Objective

Every project Cardine initializes or adopts receives `.codex/rules/meridian.rules`. ADR work
item 9 says the rules file is created under Cardine names. The file also still contains rules
for a `meridian` command that no longer exists: they match nothing, while its Git rules are
live.

Rename the file to `.codex/rules/cardine.rules` and remove the dead rules. Nothing is added:
the rules for `cardine` commands already live in the user-level
`~/.codex/rules/cardine.rules` written by `setup`, and allowing more here would widen what an
agent may do.

The steps, in order:

1. `git mv` the file in `templates/single/.codex/rules/`, in `.codex/rules/` and in
   `.cardine/baselines/1.4.0/.codex/rules/`.
2. Replace `meridian.rules` with `cardine.rules` in `capabilities/catalog-v1.json`,
   `commands/cardine-init.md`, `src/cardine/hosts/setup.py`, `src/cardine/templates/files.py`,
   `.cardine/manifest.json` and the Python test modules listed under Expected code surface.
   Files under `tests/fixtures/` do not change.
3. In the template: the first line becomes `# Cardine task-worktree command approval policy.`;
   remove the comment that starts `# Read-only and validation-only Meridian commands.` and
   the rules below it, up to the blank line; remove every other line containing `"meridian"`.
   Keep the `# Unattended-closure additions.` comment and all the Git, `python3`, `set` and
   read-only rules.
4. Copy the new template over the two other copies, so all three are identical, and set the
   digest of `.codex/rules/cardine.rules` in `.cardine/manifest.json` to the SHA-256 of the
   new file.
5. In `tests/test_codex_rules.py`, delete every expected line and every case whose command
   starts with `meridian`.
6. In `tests/test_no_meridian_identifiers.py`, delete the `Allowance` whose pattern is
   `OLD + r"\.rules\b"`, which no longer matches anything.
