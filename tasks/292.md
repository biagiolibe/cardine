## Objective

`docs/ADR_PRODUCT_DIRECTION.md`, decision 2: every stop reads as what happened, plus the
command that resumes. A troubleshooting guide collects the stops that users meet. The
registry (`capabilities/stop-codes-v1.json`) and `docs/RUN_COMMANDS.md` are references,
not a guide. Between 2026-11-11 and 2026-11-12 these situations surprised the
developer, each with a known answer:

1. `waiting` on CI for a commit with no check run: `CI_NOT_STARTED`, and pushing the
   same commit to another branch.
2. A workflow with `paths-ignore`, so a task that changes only documentation never gets a
   check run.
3. A policy change in `.cardine/project.json`:
   - the order commit, `authorize`, `contract update`;
   - `task-policy: <ID> predates main`.
4. `REVIEW_NOT_APPROVED`, with each cause: `missing` (including missing CI checks),
   `stale`, `source`.
5. "launched reviewer unavailable", and `cardine doctor`'s `role-launch-reviewer`.
6. `REVIEW_LOOP_EXHAUSTED`.
7. `INTEGRATION_CONFLICT` during a refresh from `main`.
8. "reauthorization required" after updating the runtime.
9. `self-update` printing `Latest: unknown`, before 0.10.0.
10. A landed task shown as `Closing` in the console because of a file in its old worktree
    path, before task 285.
11. A file outside the Expected code surface: the preventive scope expansion.

### The guide

Write `docs/TROUBLESHOOTING.md`.
- Each situation is one `###` entry with three short parts: **What you see** (the line
  or code), **Why**, and **What to do** (the exact command).
- Group the entries under `## CI`, `## Review`, `## Policy and authority`,
  `## Integration` and `## Updates and console`.
- Take each command from the code or `docs/RUN_COMMANDS.md`, never from memory. Check
  every stop code against the registry.

Link it:
- from the README's "Documentation" section, one line;
- from `docs/QUICKSTART.md`, one sentence at the end.
