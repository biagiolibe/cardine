## Objective

Running a project's validation commands can create files: `__pycache__/`, `.pytest_cache/`,
coverage reports. In a project that does not ignore them, the engine then treats its own
run's output as the task's work. `enforce_scope` stops with `SCOPE_CHANGE_REQUIRED`, and
`execution_source_digest` changes, so `inputs` no longer matches before a rerun. On
2026-11-08 task 196 stopped this way following the quick start on a new project, with
`__pycache__/test_example.cpython-315.pyc`.

The engine runs these commands, so it can tell what they created. In `run_task_validation`
(`src/cardine/lifecycle/validation.py`):

1. When it creates a new intent, after `commit_own_records`, it stores in the intent
   `untracked`: the sorted output of `git ls-files --others --exclude-standard -z`.
2. A helper `_restore_worktree(root, task_id, intent, path, context)` lists the same command
   again. Every path not in `intent['untracked']`, not one of `_execution_owned_paths`, and
   not under `.cardine/`, is a byproduct. It moves each one, with `shutil.move` and without
   following symlinks, to `<git common dir>/cardine-operations/<ID>.byproducts/<attemptId>/<path>`
   (through `receipts.safe_path`), removes the parent directories this leaves empty inside
   the worktree, adds the paths to `intent['byproducts']`, and saves the intent.
3. It runs after each round of commands and before the result is computed, with the
   boundaries `before_validation_restore` and `after_validation_restore`.
4. For a resumed attempt in phase `process`, it also runs right after the intent is loaded
   and before `current = inputs(...)`, so a kill between a command and the restore does not
   stop the next run.
5. A new attempt removes the previous `<ID>.byproducts` directory, so only the latest
   attempt is kept.

`run_validation_step` in `src/cardine/lifecycle/engine.py` adds one item to the result's
`diagnostics` when the intent lists byproducts: `{"code": "VALIDATION_BYPRODUCTS", "message":
"moved <n> files that validation created to <directory>: <first paths>; ignore them in
.gitignore or commit them"}`. It is not a stop.

Files ignored by Git are never touched, so dependency directories and ignored caches stay.
The candidate runs in its own checkout and does not change.

## Acceptance Criteria

- [ ] A validation command that creates an unignored file and a file in a new directory
  passes. Afterwards the worktree has neither, both are in the byproducts directory, the
  directory is gone from the worktree, and the next `cardine run` does not stop. A new test
  in `tests/test_run_validation.py` checks it, including a failed first round followed by the
  unchanged rerun.
- [ ] An ignored file created by a command stays in place, and an untracked file present
  before the attempt is not moved. The same test file checks both.
- [ ] A kill at each of the two new boundaries, and between a command and the restore,
  converges on the next `cardine run` without a stop. The same test file checks it.
- [ ] The result carries the `VALIDATION_BYPRODUCTS` diagnostic, and the outcome is
  unchanged by it.
- [ ] The repeat of an unchanged run still writes nothing.
- [ ] Only the files under Relevant Files are edited, together with this task's own
  record, handoff, and state.
- [ ] **Task validation.** After the implementation commit, `cardine run` measures the
  commands under Validation and records the results in the handoff. Never edit the
  handoff after `cardine run` has written it, and commit nothing after the candidate is
  staged.
- [ ] Every command under Validation passes.
