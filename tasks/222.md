### The defect: a rejected commit is delivered again

After `cardine review verdict <ID> CHANGES_REQUESTED`, `cardine run` must return `outcome:
iterate` so that the implementer repairs the work. It now returns `outcome: progress` and
`action: deliver`: the engine delivers the same commit the reviewer has just rejected, and
goes on to validate it and ask for review again.

`verdict.py` removes `run.delivery` on this verdict. `_committed_implementation` in
`src/cardine/lifecycle/engine.py` then finds a clean worktree whose commits since the base
change the task's files, and answers true. Commit `1f734c2` made it commit the engine's own
outputs first, so the verdict's outputs no longer keep this path from being taken.

`state['review']` already records `verdict` and `reviewed_commit`. In
`_committed_implementation`, replace the last two lines with:

```python
    changed = set(git_output(root, 'diff', '--name-only', base, 'HEAD').splitlines())
    review = state.get('review', {})
    if review.get('verdict') == 'CHANGES_REQUESTED':
        # The rejected commit is not a new delivery; only a later change to the work is.
        repaired = set(git_output(root, 'diff', '--name-only', review['reviewed_commit'], 'HEAD').splitlines())
        if not repaired - owned:
            return False
    return bool(changed - owned)
```
