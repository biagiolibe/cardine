## Objective

`cardine run` launches the reviewer on the host that `review.reviewer` names in the
declaration on `main` (`launched_reviewer_adapter` in `src/cardine/lifecycle/engine.py`,
near line 218). The project sets one host for every task. The developer cannot pick
another host for one task: no option exists, and asking the agent has no effect.

Add a runtime option, as `--ci-wait-seconds` already is:

    cardine run <TASK-ID> --reviewer codex|claude

### 1. The option

- Add `--reviewer`, with choices `codex` and `claude`, to the `run` parser in
  `src/cardine/cli.py` near line 196, and to the parser in `run_main`
  (`engine.py` near line 315).
- Pass it through `dispatch_run` and `run_validation_step` to
  `launched_reviewer_adapter(locations, host=...)`. When given, it replaces
  `review.reviewer` from `main`. When absent, nothing changes.
- The option is a runtime setting. It never changes the contract, the task state or the
  declaration. It applies only when the frozen `reviewSources` contain `launched`. Without
  `launched`, `--reviewer` is accepted and ignored, with the diagnostic
  `REVIEWER_OPTION_UNUSED` and the message "--reviewer has no effect: this task's
  reviewSources do not contain launched".
- The chosen host must still be `ready`. Otherwise the existing "launched reviewer
  unavailable" stop applies, naming that host.

### 2. Continuations keep it

When the result's `next` command is `cardine run`, it keeps `--reviewer <host>`, as the
code near line 357 keeps the wait budgets.

### 3. A launch in progress keeps its host

The launch of a reviewer for the current head is recorded under `run.hostLaunches`. If a
reviewer launch for the current head already exists on another host, `cardine run
--reviewer <other>` starts no second session. It stops with `COMMAND_REFUSED` and the
detail "a reviewer launch on <host> already exists for <head>; rerun without --reviewer
or with --reviewer <host>". After `CHANGES_REQUESTED` and a new delivery, the head
changes, so the next launch may use another host.

### 4. Documentation

In `docs/RUN_COMMANDS.md`:
- add `[--reviewer codex|claude]` to the `cardine run` row, line 12;
- add one sentence to the paragraph near line 57: `--reviewer` picks the reviewer host
  for this run in place of `review.reviewer`, needs that host to be `ready` in
  `cardine doctor`, and does not change a launch already in progress.

## Technical Context

- **Developer decision** (2026-11-12): the reviewer host can be chosen per run. It is
  a runtime option, not a record field, because the host depends on the machine, not on
  the task contract.
- The verdict already records the host: `run.hostLaunches[...]['request']['host']`.
- A diagnostic code that is not a stop needs no registry entry. If
  `tests/test_stop_registry.py` or the output schema requires one for
  `REVIEWER_OPTION_UNUSED`, stop with `BLOCKED SCOPE_CHANGE_REQUIRED` and name the file.
- Sweep before finishing: `git grep -n "lease_wait_seconds\|lease-wait-seconds" -- src/cardine`,
  so every place that forwards the run options also forwards `--reviewer`.
- During development, run tests with
  `python3 scripts/run_tests.py --parallel --module <name>`.
