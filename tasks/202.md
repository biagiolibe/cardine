## Objective

Several sessions work on this repository at once. One plans tasks in the primary checkout
while another task integrates. On 2026-11-08 a planning session left `tasks/196.md`,
`tasks/197.md` and their states untracked in the primary checkout for some minutes. Two
integration checks treat any untracked file as a change of `main`:

1. `stage` in `src/cardine/integration/merge.py` refuses with `PRIMARY_DIRTY`, a stop that
   needs a developer decision, whenever `git status --porcelain` prints anything,
   including untracked files:

   ```python
   if git_output(project_root, "status", "--porcelain"):
       raise stop_error("PRIMARY_DIRTY", "primary checkout must be clean")
   ```

2. `staged_inputs` in `src/cardine/integration/candidate.py` binds the measured candidate
   to `worktreeStatus=git_output(root, 'status', '--porcelain', '--untracked-files=all')`.
   An untracked file that appears between candidate validation and finalization makes the
   passed candidate stale, and the engine runs the full candidate validation again.

An untracked file never enters the candidate. The candidate is validated in its own
checkout of the staged tree (`candidate_checkout`), and finalization commits the index.
The only untracked file that matters is one the merge would overwrite, and `git merge`
already refuses that case.

This task:

1. makes `stage` refuse with `PRIMARY_DIRTY` only for tracked changes
   (`git status --porcelain --untracked-files=no`), or for an untracked path that the
   task's changes since the merge base would write. The message names those paths;
2. binds the candidate to `git status --porcelain --untracked-files=no` instead of
   `--untracked-files=all`.

No prototype was made: the cause is read directly from the two lines above.
