## Objective

The full suite on `main` at `93f2140` failed 10 tests (repaired by tasks 212 and 215).
CI did not report them: `.github/workflows/validate.yml` sets
`continue-on-error: true`, so a run with failures is shown as a success (`fe929ee`: `FAILED
ran=2127 failures=8 errors=3`, conclusion `success`), and `cancel-in-progress: true` cancels
the run of every commit that a newer push follows. Until now the coordinator has run the
full suite by hand after a group of tasks. This task replaces that exception: CI runs the
full suite on the task commit, and `cardine run` lands only when it is green.

### CI as a gate

In `.github/workflows/validate.yml`:

- remove `continue-on-error: true` and the comment above it;
- set `cancel-in-progress: ${{ github.ref != 'refs/heads/main' }}`, so that every commit on
  `main` keeps its result;
- add `task-*` to the `push` branches, because `ciBeforeLanding` reads the checks of the
  pushed task branch.

In `.cardine/project.json` (edit by hand: no Cardine command writes this key; a project
change affects new tasks only):

- `"ci": {"provider": "github", "requiredChecks": ["validate"]}`;
- `taskDefaults` gains `"ciBeforeLanding": true`, keeping any existing key;
- `validation.commands` gains `repository-guards`: `python3 scripts/run_tests.py --parallel
  --module test_module_inventory --module test_layout --module test_no_meridian_identifiers
  --module test_text_gates --module test_stop_registry --module test_command_word`;
- `validation.candidate.REUSE`, `BOUNDED` and `FULL` each add `repository-guards`. These
  modules read the records that closure writes, so they can give a new result on the
  candidate even when the code is unchanged (task 201 failed there).
