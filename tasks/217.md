## Objective

A failed validation leaves the engine's own outputs in the task worktree: the modified
`.cardine/tasks/<ID>.json`, and the untracked `.cardine/evidence/<ID>.json` and
`tasks/handoffs/<ID>.md`. The implementer commits the repair and is then stopped, because
both paths to a new delivery require a clean worktree and count those outputs:

- `deliver_implementation` in `src/cardine/lifecycle/delivery.py` raises `implementation
  must be committed before delivery`;
- `_committed_implementation` in `src/cardine/lifecycle/engine.py` returns false, so
  `cardine run` does not deliver.

On 2026-11-08 task 212 stopped with `COMMAND_REFUSED` for this reason, and it needs a
commit by hand of files the implementer must not otherwise touch. Task 201 hit it too.

`commit_own_records` in `src/cardine/lifecycle/validation.py` already commits these
outputs, and only when nothing else is dirty. Use it in both places, only when the status
is not clean, so a clean worktree costs no extra Git call:

```python
if git_output(root, 'status', '--porcelain'):
    commit_own_records(root, task_id, context=context)
    if git_output(root, 'status', '--porcelain'):
        raise CardineError('implementation must be committed before delivery')
```

In `_committed_implementation` the same shape returns false instead of raising. Import
`commit_own_records` inside the function if a module-level import would be circular.

  committed. The same test file checks it.

  record, handoff, and state.

  handoff after `cardine run` has written it, and commit nothing after the candidate is
  staged.
- [ ] Every command under Validation passes.
