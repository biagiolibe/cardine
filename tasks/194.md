## Objective

Two files that Cardine writes inside `.cardine/` belong to one machine:
- `.cardine/receipt-authority.json`, the accepted local authority of the checkout;
- `.cardine/task-creation.guard`, the empty file that `cardine task new` locks.

`cardine init` and `cardine adopt` ignore neither. A project shows them as untracked
after its first task, `cardine adopt` then refuses the project as dirty, and an
ordinary `git add -A` commits them. This repository committed the guard by mistake on
2026-11-07 (commit `7e3ac34`); before task 186 its authority, with absolute paths, was
one `git add -A` away from history.

Let `init` write `.cardine/.gitignore` with both names. Every adoption reuses the init
outputs, so it gets the same file. Because the file lives inside `.cardine/`, it works
whatever the project's own `.gitignore` contains; task 189 keeps that file untouched.
In this repository, ignore the guard at the root, where `.gitignore` already ignores
the authority, and stop tracking it.

- The prototype base already contains task 189, which also edits
  `src/cardine/templates/init.py`.
- Intents and stage files under `.cardine/tasks/` are transient and out of scope.
- During development, run only what the change touches: `python3
  scripts/run_tests.py --parallel --module <name>`, repeating `--module`. Do not run
  `python3 -m unittest` directly. Run the full suite once, as the counted
  clean-clone validation.
- Run validation suites one at a time and redirect each one's output to a log file
  with its exit code appended, so the result survives a lost process handle.
- Other tasks share this machine. Stop only your own processes, by process ID;
  never `pkill` test runs by pattern.
