# Task 294 — Decide how to separate user documentation from design records

Question: Which files under `docs/` are user documentation and which are design records, and what moves, link changes and test changes would put the design records under `docs/design/` without breaking a link, a test, a template or an installed project?
Timebox: one session, at most 2 hours of wall time
Deliverable: `docs/DOCS_SPLIT_PLAN.md` with the inventory, the proposed moves and the ordered work items; no file is moved

## Context

`docs/` holds about 40 files. User guides (`QUICKSTART.md`, `HOW_TO_UPGRADE.md`,
`RUN_COMMANDS.md`) sit next to ADRs and internal inventories (`FORGERY_INVENTORY.md`,
`RULE_ENFORCEMENT_INVENTORY.md`, `TEXT_GATE_INVENTORY.md`).
`docs/ADR_PRODUCT_DIRECTION.md`, decision 2, separates them.

## What the plan must settle

1. Classify every file under `docs/`, excluding `docs/assets/` and `docs/examples/`, as
   user, design, or template-copy. Template copies are files that `templates/single/`
   also ships, such as `docs/workflows/`.
2. For each design file, list every reference to its path, found with
   `git grep -n "<name>"`:
   - in the repository: README, docs, src, tests, scripts, skills, commands, templates,
     capabilities;
   - in the published release notes and the changelog, which stay as they are.
3. Name the files that must not move, and why. For example: a file named by a stable
   message, by a template, by a test fixture, or by a published link that installed
   projects follow.
4. Propose the moves as ordered work items of at most ten files each, with the link and
   test edits each needs.
