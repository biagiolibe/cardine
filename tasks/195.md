## Objective

Correcting the prose of a queued task record breaks the task. The creation receipt
covers the record bytes, so after the edit every reader of the task answers:

```text
changed or missing receipt artifact: tasks/191.md
```

`cardine task contract update <ID>` is the command for revising a record, but in
`src/cardine/tasks/contract_update.py` it returns `"updated": false` and writes nothing
when the resolved contract is unchanged, which is the case for any change to the
objective, criteria, or context. The coordinator met it on 2026-11-07 while fixing
record 191 and had to restore the old text. Decision 13 of `docs/ADR_CARDINE_1_0.md`
says no gate reads record prose, so such a correction must be possible.

When the contract is unchanged but the record bytes differ from the bytes the latest
receipts cover, write a `contract_revision` operation that covers the new record. Leave
the contract and its history unchanged. When the bytes are already covered, stay a
no-op.

## Technical Context

- `contract_revision` is an existing operation kind; `write_operation` replaces the
  record's coverage with the new digest and keeps the receipt chain.
- The command keeps its existing guards: the task lock, the creation guard, and the
  refusal of a record changed during the update.
- During development, run only what the change touches: `python3
  scripts/run_tests.py --parallel --module <name>`, repeating `--module`. Do not run
  `python3 -m unittest` directly. Run the full suite once, as the counted
  clean-clone validation.
- Run validation suites one at a time and redirect each one's output to a log file
  with its exit code appended, so the result survives a lost process handle.
- Other tasks share this machine. Stop only your own processes, by process ID;
  never `pkill` test runs by pattern.
