## Objective

Every task record repeats about 40 lines of "Developer decisions given in advance", and
every implementer reads them up front. Spike 203 (`docs/ENGINE_STOP_CLASSIFICATION.md`,
part 5) classified each line: most are now enforced by the engine or resolved by stop
fixes, and six are project-wide rules that need judgment. The developer decided on
2026-11-08 not to build the frozen-decisions mechanism of follow-ups F12 to F16. The
project-wide rules move instead to `PROJECT_WORKFLOW.md`, which every agent reads before
acting (`AGENTS.md`, `CLAUDE.md`), and the block leaves the task blueprint.

The same task fixes the one engine check that part 5 found missing (follow-up F10):
`enforce_scope` stops at the first path outside the expected surface, so a task that
needs three extra files stops three times.

### 1. Standing decisions in `PROJECT_WORKFLOW.md`

Add a section `## Standing decisions` at the end of `PROJECT_WORKFLOW.md`, outside every
`<!-- CARDINE:BEGIN ... -->` region (managed regions are rewritten by `cardine upgrade`
and checked by `cardine audit`; do not edit them). Content, one bullet each:

- The developer gives these decisions in advance for every task. They hold however the
  task is launched; none of the situations they cover needs a new decision.
- After fixing a failure, continue with `cardine run` in the same turn; do not stop to
  report the fix.
- Test runs during implementation are development, not validation attempts. Run only
  what the change touches: `python3 scripts/run_tests.py --parallel --module <name>`,
  repeating `--module` (a comma-separated list is refused). Do not run
  `python3 -m unittest` directly.
- Task validation runs the commands under the record's Validation section. Do not run
  `--clean-clone` or the full suite: the coordinator runs the full suite on `main` after
  a group of tasks, and CI runs it on every push.
- Run test suites one at a time, redirect each one's output to a log file with its exit
  code appended, and let a started run finish. Other tasks share this machine: stop
  only your own processes, by process ID, never by pattern.
- Before stopping for a change of scope, finish everything else, commit it, and run the
  repository check and the affected tests, so that one stop names every file needed.
- A recoverable result (`outcome: next`): run `next.command` unchanged. If the same code
  with the same detail comes back twice in a row, stop and report it.

### 4. Every out-of-scope path in one stop

In `src/cardine/lifecycle/scope.py`, `enforce_scope` collects the paths outside the
expected surface instead of rejecting at the first, and raises one
`SCOPE_CHANGE_REQUIRED` after the loop:

- one path: the detail stays exactly `path outside expected surface: <name>` (existing
  tests and agents read it);
- several: `paths outside expected surface: <a>, <b>, <c>`, sorted.

The other rejections in the loop (an invalid path, a symlink that escapes the project)
still raise at once: they are integrity checks, not scope.
