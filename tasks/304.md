# Task 304 — Report in cardine doctor when a project's templates are behind the runtime

## Objective

A developer who skips releases can miss template changes. `cardine self-update` decides
whether to suggest `cardine upgrade` from the kind of the target release only. Suppose a
developer skips a template-changing release and lands on a CLI-only one. The project keeps
the old managed files, and nothing tells them. Task 303 fixes the checklist. This task
makes `cardine doctor` report the gap, so a developer sees it even without updating.

`cardine doctor` (`src/cardine/cli.py`, near line 776) prints host facts only.

### 1. The fact

Add one project fact, `templates`, computed read-only from `plan_upgrade`
(`src/cardine/templates/upgrade.py`, line 27). Put the function in
`src/cardine/templates/upgrade_support.py`, next to `plan_has_blockers`. Its values:
- `ready`: every plan item is `keep`, and no migration is pending;
- `upgrade-available: <n> managed change(s), <baseline> -> <target>; run cardine upgrade --check --project <checkout>`:
  any other item, or a pending migration;
- `blocked: <n> conflict(s); run cardine upgrade --check --project <checkout>`: when
  `plan_has_blockers` is true;
- `unverified: <reason>`: when `plan_upgrade` raises, for example a missing baseline or a
  runtime older than the project baseline.

Here `<n>` counts the plan items that are not `keep`. `<baseline>` and `<target>` are the
versions that `print_plan` shows on its first line. `<checkout>` is the resolved project
path.

The fact writes nothing and calls no network. A CLI-only release must still report
`ready`, even when the manifest's `frameworkVersion` is older than the runtime.

### 2. Where it prints

`cardine doctor` prints `templates: <value>` once, before the host facts. It prints it
with or without `--host`.

### 3. Documentation

- `docs/HOW_TO_UPGRADE.md`: in the step that runs `cardine doctor`, one sentence says the
  `templates` fact shows template changes that are still to apply, including those of
  skipped releases.
- `docs/TROUBLESHOOTING.md`: one entry for `templates: upgrade-available`, with the
  commands `cardine upgrade --check` and `--apply`, then the commit.

## Acceptance Criteria

- [ ] On a project at the runtime's baseline, `cardine doctor` prints `templates: ready`.
- [ ] On a project whose baseline is older and whose managed files differ from the
  runtime's, it prints `templates: upgrade-available: ...` with the count and the
  command. This also holds when the runtime's own release is CLI-only.
- [ ] A conflicting managed file gives `templates: blocked: ...`.
- [ ] A project whose baseline directory is missing gives `templates: unverified: ...`, and

- **Developer decision** (2026-11-12): skipping releases must not hide template changes.
  The ground truth is the comparison between the project and the installed runtime, not
  the release notes.

  `present`. So `ready` is the value for an up-to-date project.
