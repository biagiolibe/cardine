## Objective

`docs/ADR_REVIEW_VERDICT_SOURCES.md`, section "Amendment (2026-11-12)", changes the
launched reviewer:
- the child has no write capability;
- Cardine reads the child's structured final answer and records the verdict itself;
- only the reviewer profile must be enforced.

This task builds that core on the existing launch machinery
(`src/cardine/hosts/launch.py`, `src/cardine/hosts/transports.py`) with a fake transport.
The host adapters (Codex, Claude) and the `cardine run` integration are later tasks.

### 1. The response carries the answer

Today a transport response is `{session, result}`, where `result` is `completed` or
`failed` (`_WRAPPER` and `poll` in `transports.py`; the check in `launch_work` near line
205). Extend the response with `output`, the parsed JSON final answer of the child.

- The wrapper reads the answer from `output.json` in the request directory. The host
  adapter's argv makes the host write it there; adapters come later.
- `output` is `null` when the file is missing or is not a JSON object.
- `launch_work` accepts `{session, result, output}`, and still accepts responses
  without `output` from records written before this change.

The answer schema is `{"verdict": "APPROVE"|"CHANGES_REQUESTED"|"BLOCKED", "findings": string}`.
Add it as `schemas/review-answer-v1.schema.json`, so adapters pass the same file to
`--output-schema` and `--json-schema`.

### 2. Only the reviewer profile is required

`ProfileAdapter.profiles` (`launch.py` near line 56) refuses unless both the implementer
and the reviewer profiles are enforced and distinct. For a reviewer launch, require only
the reviewer profile to be present and enforced. The implementer launch keeps its
current rule.

### 3. Cardine records the verdict

Add `record_launched_verdict(root, task_id, request_id)` in `src/cardine/review/verdict.py`.
It reads `run.hostLaunches[request_id]` and checks that:
- the record has a response with result `completed`;
- `output` validates against the answer schema;
- the request role is `reviewer` and its `contract`, `source` and `source_digest` equal
  the current ones, with the checks the `--request-id` branch makes today (near lines
  44 to 60).

It then records the verdict through the same write path as the owner verdict:
- the receipt, the budget and the history;
- `approved_by: reviewer`, `source: launched`;
- the findings as the review body.

An invalid or missing answer stops with `REVIEW_NOT_APPROVED` and
"cause: missing; the launched reviewer returned no valid answer". The child never needs
a credential: `_ROLE_ACTIONS['reviewer']` issues no `verdict` action.

### 4. Remove the command-line request path

Remove `--request-id` from `cardine review verdict` (`src/cardine/cli.py` near lines 402
and 873) and from its row in `docs/RUN_COMMANDS.md` line 14. The verdict command keeps
only `--owner`. Without `--owner` it refuses with "a launched reviewer's verdict is
recorded by cardine run; use --owner to record your own". The internal non-owner
branch of `record_review_verdict` goes, and `record_launched_verdict` replaces it.

### 5. Schema

In `schemas/task-state-v1.schema.json`, add `launched` to the `source` enum of `review`,
near line 142, and of the `review_history` items.

## Acceptance Criteria

- [ ] With a fake transport whose response has a valid `APPROVE` answer,
  `record_launched_verdict` records `approved_by: reviewer`, `source: launched`, and a
  receipt.
- [ ] The same verdict is refused when:
  - the HEAD moved after the request;
  - the answer is missing or invalid;
  - the request role is `implementer`;
  - the result is `failed`.
- [ ] Two consecutive launched `CHANGES_REQUESTED` end in `REVIEW_LOOP_EXHAUSTED`.
- [ ] A reviewer launch succeeds with an enforced reviewer profile and an unenforced
  implementer profile. An implementer launch still needs both.
- [ ] `cardine review verdict <ID> APPROVE` without `--owner` refuses with the message of
  part 4. `--request-id` is an unknown option.
- [ ] A response without `output`, from an older record, is still accepted by
  `launch_work`.
