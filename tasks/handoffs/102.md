### Behavior and boundary

The engine exposes `launch_run_work` using an explicitly injected Codex or Claude profile adapter. Each request binds the task, canonical worktree, attempt, contract, source, host and role profile. Its project-scoped request ID is persisted before spawn. An interrupted command looks up or atomically creates the same host session, then polls its retained terminal response. Request, session and response metadata each use RE1b operation receipts. A host response does not record delivery, acceptance or a verdict.

Profiles must be distinct and effectively enforced by the injected host. Missing/shared/unenforced profiles refuse fallback. Host credentials authorize launch independently of caller role labels; implementer credentials are denied launch, verdict, developer/owner, state/receipt and push actions in both disposable host fixtures. A second role or attempt cannot start while another issued session remains active. Foreign session identities, changed source/contract/profile and foreign pending operations are preserved and refused. Session tokens are never exchanged between roles.

These tests exercise the interface through disposable host channels. Real host enforcement remains unavailable until work item 9 installs the profiles and deny rules. Same-user receipts and hashes are not authorship proof.
