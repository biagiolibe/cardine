# Task 275 — Declare which sources may record a review verdict

> **ID**: `275`
> **Category**: Feature

> **Session**: Review verdict sources, 2026-11-11
> **Origin**: plan

## Objective

`docs/ADR_REVIEW_VERDICT_SOURCES.md` (Accepted) lets a verdict come from three sources:
`owner`, `forge` and `launched`. Its work item 2 adds the project key that restricts
them. This task builds that key, freezes it into the task contract, and makes the owner
verdict refuse when the frozen sources exclude `owner`. No new source is built here.

### 1. The declaration key

Add an optional top-level object to `.cardine/project.json`:

    "review": { "sources": ["owner"] }

- `review` is a new top-level key, next to `ci`. It is not `taskDefaults.review`, which
  stays the `required` / `not_required` string.
- `sources` is a nonempty list of distinct values drawn from `owner`, `forge`,
  `launched`. `review` has no other key.
- Only the sources that this version can record are accepted. Today that is `owner`
  alone. A known but unavailable value fails with
  "project declaration key 'review.sources': source 'forge' is not available in this version".
  An unknown value fails as an invalid value. Keep the known and the available names
  in two constants in `src/cardine/shared/project.py`, so the work item that builds a
  source adds it to the available set only.
- An absent `review` key means `["owner"]`.

Update `parse_project_declaration` (its allowed top-level keys near line 120) and
`schemas/project-v1.schema.json`. The schema lists the three known names, because the
availability check belongs to the code.

### 2. Freeze it into the contract

When the declaration has `review.sources`, task creation and `cardine task contract
update` write it into the contract as `reviewSources` (`src/cardine/tasks/contract.py`,
the returned dictionary near line 133, next to `ci`). When the declaration has no
`review` key, the contract has no `reviewSources`, so existing contracts and fixtures
stay valid. Add `reviewSources` as an optional property of `contract` in
`schemas/task-state-v1.schema.json`, with the same item enum, `minItems` 1 and
`uniqueItems`.

### 3. Refuse an excluded owner verdict

In `src/cardine/review/verdict.py`, before the owner verdict is authorized, read
`state['contract'].get('reviewSources', ['owner'])`. If it does not contain `owner`,
stop with `REVIEW_NOT_APPROVED` and the detail
"cause: source; the task contract's reviewSources (<list>) exclude owner; project key review.sources".
Cancel and abort stay owner commands and are not affected. The `--request-id` path is
not changed.

In `capabilities/stop-codes-v1.json`, update the `REVIEW_NOT_APPROVED` summary so it
names the three causes: missing, stale, or source.

### 4. Document it

In `docs/PROJECT_DECLARATION.md`, add a short section "Review sources" after the task
option table. It says:
- what the key is and what its default is;
- that it is frozen at task creation like the other options;
- that only `owner` is available in this version;
- that the ADR is the reference.

## Technical Context

- **Developer decisions** (2026-11-11):
  - The ADR is accepted; this is its work item 2.
  - The key is frozen into the contract, because `docs/PROJECT_DECLARATION.md` says
    configuration edits affect new tasks only.
  - A source is accepted in the declaration only once this version can record it. A
    project must never declare a set of sources that no command can satisfy.
- The review projection values `github`, `launched` and `forge`, and the `forge` object,
  are **not** part of this task. They move to the forge verdict work item, where a
  command first writes them. The ADR's item 2 is narrowed accordingly.
- `cardine doctor`'s `review-verdict` fact (task 273) stays correct, because only
  `owner` can be declared. The forge work items update it.
- The surface has 10 paths, because a declaration key needs
  its schema, the contract schema and the stop registry. All the edits are small.
- Sweep before finishing: `git grep -n "\"ci\"\|'ci'" -- src/cardine/shared/project.py src/cardine/tasks/contract.py`,
  so every place that lists the top-level keys or the contract keys gains `review` or
  `reviewSources`.
- During development, run tests with
  `python3 scripts/run_tests.py --parallel --module <name>`.
