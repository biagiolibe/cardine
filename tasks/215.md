## Objective

The full suite on `main` at `93f2140` fails 7 tests that this task repairs; task 212
repairs the other 3. Queued tasks run some of these modules in their own validation, so
they would stop on a failure that is not theirs.

### 1. One engine fix

Since task 202 untracked files no longer make the primary checkout dirty, so `stage` in
`src/cardine/integration/merge.py` goes on when `recover_landing_residue` has left a
pending landing residue that it could not prove owned. A later write then stops with the
untyped `pending operation must be replayed before another write`. After the
`--untracked-files=no` check, `stage` raises
`stop_error("PRIMARY_DIRTY", "pending landing residue must be resolved before staging")`
when `receipts.pending_operation(project_root, identity.canonical_id)` is true. This makes
`test_foreign_dirt_beside_owned_residue_preserves_everything` and
`test_changed_residue_bytes_stay_dirty_and_are_preserved` in `tests/test_run_recovery.py`
pass unchanged.

### 2. Test expectations the integrated tasks made obsolete

- `test_dirty_primary_checkout_stays_a_guardrail` in `tests/test_run_recovery.py`: it
  creates an untracked `foreign.txt`. Modify a tracked file instead, keeping the expected
  stop (task 202).
- `test_delivery_commits_only_owned_projections_and_is_idempotent` and
  `test_commit_failure_reports_pending_actual_state_and_recovers` in
  `tests/test_execution_boundaries.py`: `launch_command` is now `Proceed with 001` (task 192).
- `test_command_budgets_and_noop_delivery_writes_nothing` in `tests/test_command_context.py`:
  delivery now uses 48 Git calls. Raise the limit from 47 to 48.

### 3. Revision (2026-11-08)

The evidence ledger holds captured command output, so a failed attempt can record a
machine path that `scripts/check_repository.py` refuses. `MACHINE_PATH_ALLOWED_PATTERN`
becomes `re.compile(r"\.cardine/(?:tasks|evidence)/[^/]+\.json")`, as task 212 already did
on `main`, with the comment above it extended the same way.
