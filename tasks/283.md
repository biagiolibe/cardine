## Objective

Tasks 278 to 282 change the review:
- CI passes before review;
- `cardine run` launches a read-only reviewer and records its verdict when
  `review.sources` contain `launched`;
- `cardine review verdict` accepts only `--owner`.

Three managed blocks still describe the old review. A project that upgrades would get
wrong instructions:

- `templates/single/PROJECT_WORKFLOW.md`, block `review-policy v3`, says that the
  developer records every verdict.
- `templates/single/docs/workflows/REVIEW.md`, block `task-worktree-review-procedure v5`:
  - tells the reviewer to validate by running the project's commands;
  - says that only the developer records the verdict.
- `templates/single/docs/REVIEW_RECORD_TEMPLATE.md`, block `review-remediation-record v3`,
  shows `cardine review verdict` without `--owner`, which task 279 makes refuse.

### 1. `review-policy` v3 → v4

Replace the first sentence with:

"A session other than the implementer's reviews; `cardine run` records a launched
verdict, else the developer's `--owner`; nobody approves their own work."

It has 21 words against 22 today. The implementation role's start budget is full, so the
block must not grow.

### 2. `task-worktree-review-procedure` v5 → v6

- In the second paragraph, replace the sentence from "Use a completed CI run" to "never
  accept a bare "tests passed"." with:
  "Read the measured validation evidence and the required CI result for this exact
  commit; with `ciBeforeLanding`, review starts only after CI passed. Rerun a project
  command only to confirm a specific finding, never `cardine execution validate`; never
  accept a bare "tests passed"."
- In the last paragraph, replace "The developer records it from an interactive terminal
  with" with: "A launched reviewer returns it as the answer Cardine requests, and
  `cardine run` records it. In a manual session the developer records it from an
  interactive terminal with". Keep the command that follows, including
  `--owner --project <work.worktree>`.

### 3. `review-remediation-record` v3 → v4

Replace "Record each verdict with `cardine review verdict <TASK-ID>
APPROVE|CHANGES_REQUESTED|BLOCKED --body <review-evidence>` on the clean reviewed HEAD;
the owner adds `--owner`." with:

"`cardine run` records a launched reviewer's verdict; the developer records a manual one
with `cardine review verdict <TASK-ID> APPROVE|CHANGES_REQUESTED|BLOCKED --owner --body
<review-evidence>` on the clean reviewed HEAD."

### 4. Marker versions and baselines

- Bump the three markers.
- Update `requiredVersion` in `capabilities/markers-v1.json`.
- Run `python3 scripts/check_repository.py --write-marker-baselines`.

Before 1.0, template changes ship without a migration.
