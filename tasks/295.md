# Task 295 — Decide how Cardine interoperates with Spec Kit

> **ID**: `295`

Class: SPIKE
Question: How should a Spec Kit task become a Cardine task record, and how can Cardine ship as a Spec Kit extension, so that a developer specifies with Spec Kit and delivers each task with Cardine?
Timebox: one session, at most 3 hours of wall time
Deliverable: `docs/ADR_SPEC_KIT_INTEROP.md` with `Status: Proposed`, and its work items; no production code

## Context

`docs/ADR_PRODUCT_DIRECTION.md`, decisions 1 and 3: Cardine works with the developer's
spec tool, and interoperating with Spec Kit trades a competing upstream for a
distribution channel.

GitHub Spec Kit (MIT, https://github.com/github/spec-kit):
- writes a spec, a plan and a `tasks.md` before code;
- in 2026 added a `converge` step that checks finished tasks against the spec;
- has a workflow engine, tracker integrations, and a community extension catalog.

## What the ADR must settle

1. **The task format.** Mark each fact documented, with its URL, or to verify:
   - the current `tasks.md` format: identifiers, phases, parallel markers, file paths,
     dependencies;
   - where the spec and the plan live.
2. **The mapping to a Cardine record**, field by field:
   - Objective, Acceptance Criteria, Expected code surface, Dependencies, Validation;
   - what the import must ask the developer, for example the validation commands and
     the surface when the task names none;
   - how a Spec Kit task larger than about ten files is split or refused.
3. **The command.** The shape of `cardine task import`: arguments, preview with
   `--check`, idempotence on rerun, and how a changed `tasks.md` is handled.
4. **The extension.**
   - What a Spec Kit extension is: its manifest, its commands and its catalog entry,
     each with its URL.
   - What a Cardine extension would add: for example a command that hands the current
     `tasks.md` to `cardine task import`, and a step that runs `cardine run`.
   - What `converge` could read from Cardine's task state.
5. **Versioning.** How the import tolerates format changes in Spec Kit, and which Spec
   Kit versions it supports.
6. **Work items**, each about ten files.
