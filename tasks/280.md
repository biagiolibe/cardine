## Objective

`docs/ADR_REVIEW_VERDICT_SOURCES.md`, section "Amendment (2026-11-12)", requires a
launched reviewer with no write capability. For Codex, the operating system sandbox
enforces it. This task adds three things:
- the Codex reviewer launch;
- a reviewer policy defined by the absence of writes, instead of a deny-list;
- a `cardine doctor` proof that runs real write attempts under that sandbox, without a
  model call.

### 1. The reviewer policy and probes

In `src/cardine/hosts/permissions.py`, replace the reviewer probe matrix
(`_base_probe_matrix`, near lines 496 to 537) with a no-write matrix:
- `deny`: a write in the task worktree, a write to the task state under `.cardine/tasks/`,
  a write under `.git/`, and running `cardine review verdict 001 APPROVE --owner`, which
  must fail because it writes;
- `allow`: a read of a tracked file in the task worktree.

The implementer matrix does not change.

In `src/cardine/hosts/codex.py`, the reviewer `RolePolicy` describes the launch flags
instead of rules and a profile table:

    {"sandbox": "read-only", "ephemeral": true, "answer_schema": "review-answer-v1"}

Its digest is `policy_digest("codex", "reviewer", settings)`. `codex_role_policy` for the
implementer does not change.

### 2. The launch

`CodexTransport.argv` (`src/cardine/hosts/transports.py`, near line 223), for the
reviewer:

    <codex> exec --sandbox read-only --ephemeral --skip-git-repo-check --output-schema <schemas/review-answer-v1.schema.json> -o <request dir>/output.json <prompt>

The prompt is built by a new `reviewer_prompt(request)` in `transports.py`, shared with
the Claude adapter. It names:
- the task ID, the record path and the reviewed commit;
- `review.diff`, a file that the transport writes in the request directory before the
  launch, holding `git diff <recorded base>..<reviewed commit>`. A Claude reviewer cannot
  run commands, so the diff is always a file;
- the measured evidence file and the CI result;
- the rules: review correctness, scope and missing tests; edit nothing; end with the
  answer that the schema requires.

Keep the prompt under 250 words.

### 3. The doctor proof

In `role_launch_states` (`src/cardine/hosts/setup.py`, near line 962), for Codex and the
reviewer role, build the proof with a new evaluator. For each probe of part 1, it runs
the probe command through `codex sandbox` with the read-only selection that part 4
establishes, in a temporary copy of a minimal Git repository, never in the real project.
It records `deny` when the command fails and the target is unchanged, and `allow` when a
read succeeds.

`role-launch-reviewer` is `ready` only when every probe matches. Otherwise it is
`unsupported (D3)` with the gaps, as `prove_role_policy` reports today. The evaluator
calls no model and writes only in its temporary directory.

### 4. Verify the sandbox selection first

Before writing part 3, find by trial on this machine which `codex sandbox` options run a
command under the same read-only policy as `codex exec --sandbox read-only`. Candidates
are `-c sandbox_mode="read-only"` and `-P <permission-profile>`.

These trials are local and call no model. Run them in a temporary directory. Record in
`docs/HOST_CAPABILITY_CONTRACT.md`, as a new dated row of the probe table:
- the Codex version;
- the selection used;
- that a write to the working directory was refused;
- that a user `~/.codex/config.toml` with `sandbox_mode = "danger-full-access"` does not
  widen a `codex exec --sandbox read-only` session.

The last check needs a model call. Do not run it: mark it "to verify by the developer"
in the row.

If no selection reproduces the read-only policy, stop with `BLOCKED` and report what
you tried.
