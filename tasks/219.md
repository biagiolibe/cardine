## Objective

Tasks run in parallel, and only one can integrate at a time. On 2026-11-08 `cardine run 211`
stopped with `WRONG_WORKTREE` and `human_decision: true` because task 196 held the
integration lease. Nothing needed a person: the same command worked once the lease was
released.

`run_integration_step` in `src/cardine/lifecycle/engine.py` already waits with
`wait_for_lease`, but only when the task's worktree exists. For a task that has no worktree
yet, it returns `None` and `run_worktree_step` reaches the `integration-active` refusal in
`src/cardine/lifecycle/execution.py`. A later step can reach the same kind of refusal while
only the lease file exists.

Change `dispatch_run`: before it calls `run_worktree_step` and before it calls
`run_validation_step`, it calls one helper:

```python
def _integration_wait(locations):
    from cardine.integration.candidate import wait_for_lease
    if wait_for_lease(locations):
        return None
    argv = ['cardine', 'run', locations.task_id, '--project', str(locations.primary)]
    return envelope(locations.task_id, str(locations.primary), step='candidate', outcome='waiting',
                    action='wait-for-lease', retry_after_seconds=5,
                    next_command=command_reference(argv, 'Wait for the competing integration'))
```

A non-`None` result is returned as the step's result. `wait_for_lease` keeps refusing a lease
whose ownership cannot be verified, so that stays a stop.

Also fix `run_integration_step`. When `prepare` is false and the staged file belonged to
another task, the file is gone after `wait_for_lease` returns, and the next line would prepare
a candidate for a task that did not ask for one. After the wait, return `None` when
`staged` does not exist and `prepare` is false.
