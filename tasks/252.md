# Task 252 — Align the Claude plugin during setup and self-update

> **ID**: `252`
> **Category**: Feature
> **Priority**: 🟠 P2
> **Estimate**: ~3h
> **Assigned to**: unassigned
> **Session**: Onboarding, 2026-11-11
> **Origin**: P5 and P6 of the onboarding design

## Objective

1. Show `absent`, `match` or `mismatch` in `cardine setup --check` using
   `claude_plugin_state`. In developer-terminal `setup --apply`, share an
   alignment routine with self-update. A match needs no plugin operation.
   An absent plugin runs these commands in order:

   ```sh
   claude plugin marketplace add biagiolibe/cardine#v<version>
   claude plugin install cardine@cardine
   ```

   On mismatch, run `claude plugin marketplace remove cardine` before add and
   install. If Claude is absent from PATH, print the add and install commands.
   The subcommand spellings were verified using `claude plugin --help` and
   `claude plugin marketplace --help`.
2. Extend self-update to detect whether pipx, uv or an editable Git checkout
   owns the running CLI. Base the detection on the executing installation.
   For pipx or uv, reinstall from the requested Git tag or the latest release
   resolved by `--check-latest`. Preserve existing `--check`, `--apply` and
   clone behavior, including resumable clone updates. Keep previews read-only.
   After a successful apply, align the plugin to the newly installed version.
3. After updating, report any checkout with a stale accepted runtime and its
   exact `cardine authorize --apply --project <path>` command. There is no
   checkout registry. Limit the report to the current checkout selected by
   `--project`. Self-update never executes authorization.

## Acceptance Criteria

- [ ] Setup preview reports plugin state without running mutating commands.
  Apply covers absent, match, mismatch and missing executable using an
  injected runner. A failed command reports the cause and a retry converges.
- [ ] Injected runners verify installer detection and target selection for pipx,
  uv and editable clones, explicit and latest releases, and failures before
  plugin alignment. No test invokes Claude or a network service.
- [ ] Existing clone update tests pass. Plugin alignment uses the resulting
  version. A stale checkout is listed with a quoted command, and no
  authorization or unrelated checkout mutation occurs.
- [ ] The public surface documents setup preview and self-update modes and
  options. Any new stop emitter is recorded in `EMITTER_CAUSES`.
- [ ] The repository checks and targeted validation pass.
