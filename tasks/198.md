## Objective

Updating the installed Cardine framework stops every task that is in progress. On
2026-11-07 the developer updated `~/cardine-fw`, ran `cardine authorize`, and relaunched
task 178, which stopped with:

```text
BLOCKED WRONG_WORKTREE: execution worktree verification: preparation-receipt-mismatch
```

Operation bindings embed the value of `receipts.require_authority`: the worktree
preparation file under `.git/cardine-worktrees/`, intents, and the bindings kept in task
state (candidate validation, host launches, owned abort). That value contains the
digest of the executing runtime. Every check compares the stored binding with a fresh
`require_authority` for equality, so after an accepted runtime update no binding
matches. The developer had to remove the worktree and the branch and start the task
again.

The runtime digest is already checked where it belongs: `require_authority` refuses
until the local `.cardine/receipt-authority.json` names the running runtime, and only
the developer accepts a new one with `cardine authorize`. Bindings do not need to
repeat it. This task:

1. makes `require_authority` return the accepted authority without `runtime`, through a
   new `receipts.bound_authority`, so bindings no longer embed it;
2. makes `cardine authorize` keep the accepted `main` when the checkout, its Git common
   directory, the roots, and the policy are unchanged and the accepted `main` is still
   an ancestor of the observed `main`. Otherwise a runtime update would also move
   `accepted_main` and break the bindings that embed it;
3. drops `runtime` from the `required` keys of the four binding authority objects in
   `schemas/task-state-v1.schema.json`, keeping it under `properties` so that states
   written before this task still validate.

## Technical Context

- About fifteen call sites compare a stored binding with `require_authority(...)`:
  `worktree/preparation.py`, `integration/candidate.py`, `finalize.py`, `cleanup.py`,
  `residue.py`, `records.py`, `lifecycle/preview.py`, `delivery.py`, `control.py`, and
  `receipts.py` itself. They all keep working unchanged because both sides now come
  from the same function.
- `write_operation` already reduces the receipt authority to `portable_authority`, so
  receipts are unaffected.
- The fixture in `tests/task_contract_support.py` re-seals preparation receipts with the
  authority it accepts. Without the one-line change it wrote the full authority, and
  fourteen tests in `test_execution_boundaries` and `test_task_close` stopped with
  `preparation-receipt-mismatch`.
- **One last break.** Bindings written before this task lands still contain `runtime`,
  so a task that is in progress when the developer installs this change will stop once
  more with `preparation-receipt-mismatch`. The coordinator will tell the developer to
  update `~/cardine-fw` past this task only when no task is in progress. The task does
  not add compatibility code for those bindings.
- During development, run only what the change touches: `python3
  scripts/run_tests.py --parallel --module <name>`, repeating `--module`. Do not run
  `python3 -m unittest` directly. Run the full suite once, as the counted
  clean-clone validation.
- Run validation suites one at a time and redirect each one's output to a log file
  with its exit code appended, so the result survives a lost process handle.
- Other tasks share this machine. Stop only your own processes, by process ID;
  never `pkill` test runs by pattern.
