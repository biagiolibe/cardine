## Objective

Release 0.10.0 changes managed templates (tasks 266, 273 and 283), so its notes must start
with `Template-changing release:` and its record `releases/0.10.0.json` must say
`baselineChanged: true`. Two things depend on that:
- `scripts/prepare_release.py` requires the kind line to agree with `baselineChanged`;
- `cardine self-update` reads the kind line, and task 289 prints the
  `cardine upgrade` steps only for a template-changing release.

`check_releases` in `scripts/check_repository.py`, near line 736, fails with
"baselineChanged must be true iff migrations is non-empty". Before 1.0, template changes
ship without a migration (`migrations/README.md`, `docs/RELEASING.md`), and
`cardine upgrade` delivers them through the capability markers. So no
template-changing release can pass the repository check before 1.0.

### The rule

In `check_releases`:
- A record with migrations keeps the current rule: `baselineChanged` must be true.
- A record with version below `1.0.0` and no migrations may have `baselineChanged` true
  or false.
- From `1.0.0`, `baselineChanged` must equal `bool(migrations)`, as today.

For a pre-1.0 record with `baselineChanged: true` and no migrations,
`workflowBaselineVersion` must equal its own `version`. The existing rule that the
baseline is never ahead of the version still applies.

Update `docs/RELEASING.md`, step 2, with one sentence: before 1.0, a template-changing
release sets `baselineChanged: true` with no migrations, and `workflowBaselineVersion`
equals its version.
