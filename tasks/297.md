## Objective

Release 0.10.0 tells the user to run `cardine doctor` without `--host`, in these places:
- the next-steps checklist of `cardine self-update` (`src/cardine/release/update.py`,
  near line 348);
- the next steps of `cardine setup` (`src/cardine/hosts/setup.py`, near line 492);
- the "launched reviewer unavailable" refusals (`src/cardine/lifecycle/engine.py`, near
  lines 235 to 249);
- `docs/HOW_TO_UPGRADE.md`, `docs/PROJECT_DECLARATION.md` and the 0.10.0 upgrade notes.

`cardine doctor` requires `--host` (`src/cardine/cli.py`, near line 313), so every one of
these fails with a usage error. A consumer met it on 2026-11-12 after upgrading.

### 1. `--host` becomes optional

- Without `--host`, `cardine doctor` checks both hosts, Claude first, then Codex. Before
  each host's facts it prints a line `host: claude` or `host: codex`.
- With `--host`, the output is exactly as today, with no `host:` line.
- The exit status does not change.
- Keep `choices=("claude", "codex")`.

### 2. The reviewer refusals name the host

In the three "launched reviewer unavailable" messages, replace `run cardine doctor` with
`run cardine doctor --host <host>`, using the host the launch chose.
