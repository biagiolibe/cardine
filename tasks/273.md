## Objective

A consumer on the governed preset, with host Claude, could not approve a task.

- The review templates tell the reviewer session to record its verdict with
  `--request-id <launch-request-id>`. That path needs a reviewer session that Cardine
  launched (`run.hostLaunches`, `src/cardine/review/verdict.py` near lines 44 to 60).
  No host adapter exists: `src/cardine/hosts/launch.py` says "No adapter is installed
  by default", and `cardine doctor` reports `role-launch-reviewer: unsupported (D3)`.
- The only working path is the developer's owner verdict, from the decision 14
  amendment of 2026-11-03 in `docs/ADR_CARDINE_1_0.md`. `cardine run` prints it
  (`src/cardine/lifecycle/engine.py` near line 174), but no template says so.
- During review, `cardine run` leaves the task state, the handoff and the evidence file
  uncommitted, and commits them only at closure (`Record <ID> measured closure`,
  `src/cardine/integration/records.py` line 81). The verdict accepts them only while
  uncommitted and equal to their receipts (`_clean_review_outputs`,
  `verdict.py` near line 116). The template says "a clean worktree", so the reviewer
  committed them, and `APPROVE` was then refused as stale (`verdict.py` near line 86).

Spike 272 decides the sources of a verdict beyond the owner. This task makes the
templates and the doctor match what 0.9.2 does today.

### 1. `templates/single/PROJECT_WORKFLOW.md`, block `review-policy` v2 → v3

Replace the first sentence of the block with:

"A session other than the implementer's reviews; the developer records the verdict with
`cardine review verdict --owner`; nobody approves their own work."

The block has the same number of words, which matters because the implementation role's
start budget is full. The spike sentence stays.

### 2. `templates/single/docs/workflows/REVIEW.md`, block `task-worktree-review-procedure` v4 → v5

- In the first paragraph, after "with a clean worktree", add: ", apart from the task
  state, handoff and evidence file that `cardine run` keeps uncommitted until landing.
  Never stage, commit or edit them."
- In the second paragraph, after "otherwise validate within the diff's scope", add:
  "by running the project's commands, not `cardine execution validate`".
- Replace the last paragraph's first two sentences, from "Record the verdict" to
  "binds the verdict to that HEAD.", with:
  "End with the verdict, `APPROVE`, `CHANGES_REQUESTED` or `BLOCKED`, and its evidence.
  The developer records it from an interactive terminal with
  `cardine review verdict <TASK-ID> <VERDICT> --owner --project <work.worktree> --body <review-evidence>`,
  which binds it to the reviewed HEAD."
- In the same paragraph, replace "Commit only the files it wrote." with "Commit
  nothing.".

The rest of the paragraph stays, from "Edit no implementation file" to
`REVIEW_LOOP_EXHAUSTED`. So does the advice paragraph.

### 3. Marker versions and baselines

- Bump the two markers in the templates.
- Update `requiredVersion` in `capabilities/markers-v1.json`.
- Run `python3 scripts/check_repository.py --write-marker-baselines`.

Before 1.0, template changes ship without a migration (`migrations/README.md`).

### 4. `cardine doctor`: say who records verdicts

In `host_doctor` (`src/cardine/hosts/setup.py` near line 850), add one fact,
`review-verdict`, for both hosts:
- `launched reviewer or owner`, when `role-launch-reviewer` is `ready`;
- otherwise `owner only; record verdicts with cardine review verdict <TASK-ID> <VERDICT> --owner from an interactive terminal`,
  followed by `; required by default in this project` when the resolved task default
  `review` is `required`.

A project declaration that cannot be read leaves out the suffix and never fails the
doctor.
