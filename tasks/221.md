## Objective

On 2026-11-08 `cardine run 219` stopped with `COMMAND_REFUSED: foreign integration output
preserved during finalize` and `human_decision: true`. Nothing needed a person. 219 had
already landed, and only its cleanup was left.

`finish_delivery` in `src/cardine/integration/cleanup.py` calls `finalize_candidate` again
whenever the cleanup intent does not exist yet. In `finalize_candidate`
(`src/cardine/integration/finalize.py`), the first `_check_files` runs before anything
looks at `intent['result']`, so the lease of the next task to integrate is reported as
foreign output. Once that lease is gone, a tracked change in the primary checkout refuses
the same replay with a misleading message (`advanced main does not prove the completed
owned landing`, or `main does not match the intended landed commit`).

Task 220 does not cover this. `_cleanup_wait` in `src/cardine/lifecycle/engine.py` handles
only `CLEANUP_BLOCKED` when the cleanup intent exists; here the refusal is an untyped
`CardineError`, and the cleanup intent does not exist yet.

### 1. A completed landing with none of its own files left is not replayed

In `src/cardine/integration/finalize.py`, add next to `_check_files`:

```python
def _landing_complete(locations, intent, lease, staged):
    """A recorded landing with none of its own files left has nothing to replay."""
    binding, result = intent['binding'], intent['result']
    if result is None:
        return False
    for path, expected in ((lease, binding['lease']), (staged, binding['staged'])):
        content = _bytes(path)
        if content is not None and receipts.digest(content) == expected:
            return False
    root, landed, output = locations.primary, result['merge_commit'], intent['workerState']
    return (not _run_git(root, 'merge-base', '--is-ancestor', landed, 'HEAD').returncode
            and git_output(root, 'show', '-s', '--format=%T', landed) == binding['tree']
            and git_output(root, 'show', '-s', '--format=%P', landed).split() == [binding['main'], binding['source']]
            and receipts.digest(receipts.safe_path(locations.worktree, output['path']).read_bytes()) == output['before'])
```

and, immediately before the first `_check_files(intent, lease, staged)` of
`finalize_candidate` (the one right after the `finalize task inputs changed` refusal):

```python
        if _landing_complete(locations, intent, lease, staged):
            return intent['result']
```

An own lease or staged file that is still present means an interrupted finalize: the
function returns `False` and the existing replay releases them and restores the task
state. Do not change anything else in `finalize_candidate`.

### 2. A completed finalize counts as a started cleanup

After part 1, the replay returns and `_inactive` raises `CLEANUP_BLOCKED` for the other
task's lease, before the cleanup intent exists. In `src/cardine/lifecycle/engine.py`,
`_cleanup_wait` must wait in that case too. Replace its condition with:

```python
    if error.code != 'CLEANUP_BLOCKED' or not _cleanup_started(locations):
        return None
```

and add next to it:

```python
def _cleanup_started(locations):
    """Cleanup begins when its intent exists or when the landing is already recorded."""
    from cardine.integration.candidate import operation_path
    from cardine.lifecycle import receipts
    if operation_path(locations, 'cleanup').exists():
        return True
    finalize = operation_path(locations, 'finalize')
    return finalize.exists() and receipts._load_intent(finalize)['result'] is not None
```

Remove `operation_path` from the import inside `_cleanup_wait` if it is no longer used
there.
