## Objective

On 2026-11-11 the coordinator followed `docs/QUICKSTART.md` from the terminal in a
clean environment. At the `implementation` step, `cardine run 001` returned the same
`next` command with the reason `Obtain committed implementation and acceptance
evidence`, call after call. The quick start says to run it again until `done`, and
nothing says that the user makes the change in the task worktree named by
`work.worktree` and commits it there. Once the change was committed in the worktree,
six more calls landed the task.

Make these edits, with the text exactly as given.

### 1. The `next` reason

In `src/cardine/lifecycle/engine.py`, replace the reason
`Obtain committed implementation and acceptance evidence` with
`Make and commit the change in the task worktree, then run this command again` at both
sites: the `implementation` result near line 169, and the `execution-start` envelope
near line 530.

### 2. `docs/QUICKSTART.md`

Replace the paragraph that starts with `Run `cardine run 001` again after each step`
with:

    `cardine run` prints JSON. When `step` is `implementation`, make the change in the
    directory that `work.worktree` names and commit it there; that worktree is the
    task's branch, not your checkout. Then run `cardine run 001` again after each step,
    following the `next` command it prints, until it reports `done` or a stop with its
    reason and the command to resume. The full record format is in
    `tasks/TASK_BLUEPRINT.md` in your project. For advanced validation settings, see
    `cardine init --help`.

Write it unindented in the file.
