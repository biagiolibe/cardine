## Objective

The README installs Cardine with `pipx install git+https://github.com/biagiolibe/cardine@v0.9.2`.
On 2026-11-11 the coordinator installed `main` that way, in a clean environment, and
ran `cardine setup --check`. The package ships `cardine/_framework/skills/` with both
skills, but setup reported:

    codex-skill-cardine-project: skipped (.../.agents/skills/cardine-project; framework root is not the root of a Git checkout)

A Codex user who follows the documented install gets no Cardine skills. The same
output also advised `export CARDINE_ROOT=<venv>/site-packages/cardine/_framework` and
`export PATH="$CARDINE_ROOT/bin:$PATH"`. `_framework` has no `bin`, and a pipx install
already puts `cardine` on `PATH`.

Make these edits.

### 1. Accept the installed package's framework

In `_framework_skill_links` in `src/cardine/hosts/skills.py`, a framework root is a valid
link source when either:
- it is the root of a Git checkout, as today; or
- it is an installed package's bundled framework: a directory named `_framework`, with a
  `VERSION` file, whose parent directory is named `cardine` and contains `__init__.py`.

Any other root keeps the `skipped` state and its reason. A Claude plugin cache
directory, for example, stays skipped. The missing-assets check, the link states and
the old-link removal are unchanged.

### 2. No shell-profile advice for an installed package

In `print_setup_plan` in `src/cardine/hosts/setup.py` (near line 529), print the
`shell-profile-CARDINE_ROOT` and `shell-profile-PATH` lines only when the framework root
is the root of a Git checkout. The `CARDINE_ROOT:` state line stays.

### 3. `CHANGELOG.md`

In the `### Fixed` list of `## [0.9.2] - 2026-11-11`, after its last entry, add:

    - `cardine setup` links the Codex skills from a pipx or uv installation, and no
      longer suggests a `CARDINE_ROOT` export for one.

Write it unindented in the file.
