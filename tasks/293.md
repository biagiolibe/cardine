## Objective

`docs/ADR_PRODUCT_DIRECTION.md`, decision 2: a policy change takes one guided step. Today
a change to `.cardine/project.json` needs three steps that the developer must know:
1. commit the declaration on `main`;
2. run `cardine authorize --apply`;
3. run `cardine task contract update <ID>` for every queued task, then commit the state
   files.

Queued tasks keep the frozen contract of the old declaration. A consumer on 2026-11-11
kept running tasks with stale validation lists because step 3 was missing.

### 1. `authorize --check` names stale queued contracts

`print_authorization_plan` (`src/cardine/lifecycle/authorization.py`, near line 149)
already prints `task-policy:` lines for prepared worktrees. For every task with status
`queued` whose contract `projectDigest` differs from the digest of the declaration on
`main`, add one line:

    task-contract: <ID> was frozen under an older declaration; authorize --apply --update-queued refreshes it

Compute the digest as `src/cardine/tasks/contract.py` does near line 136.

### 2. `authorize --apply --update-queued`

Add the flag `--update-queued` to `cardine authorize` in `src/cardine/cli.py`. With
`--apply`, after the authority is accepted, Cardine calls `update_task_contract`
(`src/cardine/tasks/contract_update.py`) for each queued task of part 1:
- it prints one line per task, updated or unchanged;
- it ends with the exact `git add` and `git commit` command for the changed state files.

Cardine does not commit. A task whose update fails is listed with its error, and the
others still update. The command exits 1 when any task failed.

Tasks in progress are not touched: `cardine run` already merges `main` into them.

### 3. Documentation

In `docs/PROJECT_DECLARATION.md`, section "Change the declaration" (task 271), replace
the per-task `contract update` step with `cardine authorize --apply --update-queued`.
