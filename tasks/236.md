## Objective

For Claude Code, the plugin is the only channel that delivers the `cardine-delivery` and
`cardine-project` skills and the slash commands. Codex gets the skills from `cardine
setup`. Four defects keep the plugin from working with 0.9.0.

### 1. The slash commands run a second runtime

Every command in `commands/` runs `${CLAUDE_PLUGIN_ROOT}/bin/cardine`, the copy in the
plugin cache. The receipt authority binds one runtime per checkout, so a project
authorized for the installed CLI stops with `developer reauthorization required` when a
slash command runs the plugin's copy. ADR decision 9 states that the plugin calls the
installed CLI.

In `commands/cardine-adopt.md`, `commands/cardine-audit.md`, `commands/cardine-init.md`,
`commands/cardine-task.md`, and `commands/cardine-upgrade.md`, replace every
`"${CLAUDE_PLUGIN_ROOT}/bin/cardine"` and every `${CLAUDE_PLUGIN_ROOT}/bin/cardine` with
`cardine`. In `commands/cardine-upgrade.md`, replace `Run the CLI from this plugin source.
First inspect the plan:` with `Run the installed `cardine` CLI. First inspect the plan:`.

### 3. `cardine doctor` does not compare the plugin with the CLI

ADR decision 9 states that `cardine doctor` checks that the plugin and the CLI versions
match. In `src/cardine/hosts/claude.py`, add:

```python
def claude_plugin_state(home: Path, framework_root: Path | None) -> str:
    """The installed Cardine plugin against this CLI; read only, and never proof of activation."""
    registry = home / ".claude/plugins/installed_plugins.json"
    try:
        entries = json.loads(registry.read_text(encoding="utf-8"))["plugins"]["cardine@cardine"]
        versions = sorted({entry["version"] for entry in entries})
    except (OSError, ValueError, KeyError, TypeError):
        return "absent"
    if not versions:
        return "absent"
    if framework_root is None:
        return "installed " + ", ".join(versions)
    from cardine.release.version import read_version
    cli = read_version(framework_root)
    stale = [version for version in versions if version != cli]
    if not stale:
        return "match"
    return f"mismatch: plugin {', '.join(stale)}, CLI {cli}; reinstall the plugin at tag v{cli}"
```

Add `import json` if the module lacks it. In `src/cardine/hosts/setup.py`, give
`claude_doctor` a keyword argument `framework_root: Path | None = None`, add
`"claude-plugin": claude_plugin_state(home, framework_root),` to its result after
`claude-command-policy`, and pass `framework_root=options.get("framework_root")` from
`host_doctor`. The CLI already passes `framework_root` to `host_doctor`.

### 4. The README does not say how to install the plugin

In `README.md`, section `Install`, after the code block that ends with `cardine --version`
and before the paragraph that starts with `` `pipx install cardine` ``, add:

````markdown
For Claude Code, also install the plugin, pinned to the same tag. It provides the
`cardine-delivery` and `cardine-project` skills and the slash commands, which call the
installed `cardine`. Codex receives the skills from `cardine setup`.

```bash
claude plugin marketplace add biagiolibe/cardine#v0.9.0
claude plugin install cardine@cardine
```

`cardine doctor --host claude --project .` reports whether the plugin version matches the
CLI.
````

## Technical Context

- By developer decision, no prototype was made. The registry format comes from the
  developer's `~/.claude/plugins/installed_plugins.json`: `{"version": 2, "plugins":
  {"<name>@<marketplace>": [{"scope", "installPath", "version", ...}]}}`.
- `claude-plugin` reports an installation, not an activation: the plugin can be installed
  and disabled at a scope. The doctor never infers enforcement from it.
- The plugin ships no hooks: `cardine setup` registers them in the user registry.
- The project's standing decisions are in `PROJECT_WORKFLOW.md`, section `Standing
  decisions`.
