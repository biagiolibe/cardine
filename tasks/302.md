## Objective

The developer wants one command that updates Cardine and every project that uses it
(task 303). Cardine does not know which checkouts use it: each checkout keeps its runtime
acceptance inside its own `.git`. This task adds a small machine-local registry and a
command to see and tidy it.

### 1. The registry

Add `src/cardine/shared/projects_registry.py`, which manages `~/.cardine/projects.json`:

    {"version": 1, "projects": [{"path": "<absolute checkout path>", "addedAt": "<UTC ISO>", "lastSeen": "<UTC ISO>"}]}

- It stores only absolute paths of primary checkouts and two timestamps. It never stores
  a remote URL, a branch, a token or project content.
- Writes are atomic and owner-only (mode 0600). The `~/.cardine` directory is created with
  mode 0700 when missing.
- `record(path)` adds the checkout, or updates its `lastSeen`. It resolves the primary
  checkout first, so a task worktree path records its primary checkout.
- `entries()` returns each path with three facts:
  - `exists`: the directory exists;
  - `configured`: `.cardine/project.json` is present;
  - `accepted`: the checkout holds a runtime acceptance, as `stale_runtime_report` in
    `src/cardine/release/installer.py` checks it.
- A missing or corrupt file reads as empty. A corrupt file is never overwritten without
  first being renamed to `projects.json.corrupt-<timestamp>`.

### 2. Who records

Call `record` after these succeed:
- `cardine init --apply`, and the interactive `cardine init` when it applies;
- `cardine adopt --apply`;
- `cardine authorize --apply`.

A failure to record never fails the command: it prints one `warn` line.

### 3. `cardine projects`

Add the command `cardine projects` to `src/cardine/cli.py`. It is marked experimental in
its help, as `cardine console` is.
- Without options, it lists each entry with its three facts, one line each.
- `--forget <path>` removes one entry.
- `--prune` removes the entries whose directory no longer exists, and prints them.

None of them touches a project.

### 4. Documentation

- Add `cardine projects` to `docs/RUN_COMMANDS.md`.
- Add it to `docs/PUBLIC_SURFACE.md` as `Experimental`.

  - `init --apply`, `adopt --apply` and `authorize --apply` each leave one entry for the
