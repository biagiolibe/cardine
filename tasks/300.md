## Objective

On 2026-11-12, spike 294 delivered its plan, passed validation and CI, then stopped
during integration with:

    TASK_STATE_INVALID: spike landing requires an outcome

That check lives in `src/cardine/integration/merge.py`, near line 129. The code is the
generic one for corrupt state. The message names neither the developer's decision nor
the command. The implementing agent reported the task as blocked and could not say what
to do. The fix is `cardine task outcome <ID> ANSWERED|INCONCLUSIVE`, which records the
developer's judgment.

### 1. A dedicated stop, raised before integration

Add the stop code `SPIKE_OUTCOME_REQUIRED` to `capabilities/stop-codes-v1.json`,
following the entry of `CI_NOT_STARTED`:
- class `tool`, kind `stop`, `human_decision` true, resolution `recoverable`;
- `test` names the new test.

Register its cause in `src/cardine/stops/causes.py`.

In `run_worktree_step` (`src/cardine/lifecycle/engine.py`), stop with it when all of
these hold:
- the task class is `spike` and no outcome is recorded;
- validation passed;
- CI passed, when the contract requires it;
- review is approved, when the contract requires it.

Raise it before the candidate or any integration step starts. The detail is:

    spike <ID> needs your judgment: does the committed deliverable answer its Question within its Timebox? Record it with cardine task outcome <ID> ANSWERED --project <worktree>, or INCONCLUSIVE

The resume is the same `cardine run` command.

### 2. The late check

Keep the check in `merge.py` as a guard, but raise `SPIKE_OUTCOME_REQUIRED` there with the
same detail instead of `TASK_STATE_INVALID`.

### 3. What the developer must do after `task outcome`

Find out with a test whether the outcome that `cardine task outcome` records in the task
worktree must be committed before `cardine run` accepts it.
- If it must, `cardine task outcome` commits it on the task branch itself, with the
  message `Record spike <ID> outcome`.
- If it need not, change nothing.

Either way, the developer runs exactly two commands: `task outcome`, then `cardine run`.

### 4. Documentation

- `docs/TROUBLESHOOTING.md`: one entry under `## Review` or `## Integration` for
  `SPIKE_OUTCOME_REQUIRED`, with its two commands.
- `docs/RUN_COMMANDS.md`: one sentence in the spike paragraph, or near the list of
  outcome classes.
