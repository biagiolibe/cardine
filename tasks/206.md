## Objective

Spike 203 (`docs/ENGINE_STOP_CLASSIFICATION.md`) classified every refusal on the path of
a task. The developer decided on 2026-11-08 to convert only the refusals that actually
stopped tasks, and to leave the rest fail-closed until a task meets them. This task does
three things.

### 1. A stale candidate owned by the task is reversed by the engine

On 2026-11-08 task 198 stopped with `COMMAND_REFUSED: foreign candidate ownership or
changed task source`. The lease and the staged file were intact and owned by 198; only
the task branch had moved past `staged.task_commit` (a commit was added in the worktree
after staging). The coordinator had to read the source to find this, and fixed it by
moving the branch back.

Today:

- `staged_inputs` in `src/cardine/integration/candidate.py` joins an ownership check and
  a changed-source check in one untyped `CardineError('foreign candidate ownership or
  changed task source')`, which `dispatch_run` turns into `COMMAND_REFUSED`
  (`human_decision: true`).
- `verified_candidate` calls `staged_inputs` from `run_integration_step`
  (`src/cardine/lifecycle/engine.py`) before candidate validation, so the
  `EVIDENCE_MISMATCH` refusals of `staged_inputs` ("candidate tree or main changed", "task
  lifecycle authority changed after staging", "task source or contract changed after
  staging") reach the developer as well, although `EVIDENCE_MISMATCH` is registered
  `recoverable` and rerunning reproduces it.
- The engine's own reversal, `recover_task_integration` (`src/cardine/integration/merge.py`,
  `abort_owned` with `ENGINE_PRINCIPAL` in `src/cardine/lifecycle/control_abort.py`),
  refuses this case too: it requires `MERGE_HEAD == staged.task_commit == worker HEAD`
  and raises `foreign or unverified merge target` otherwise.

Change:

- Split the first check of `staged_inputs`. A lease or staged file that names another
  task, project or branch, or staged keys that differ from the lease, is an integrity
  failure: raise `stop_error('INTEGRITY_MISMATCH', ...)` with the message format of
  part 2. A `staged.task_commit` that differs from the worker HEAD is a stale candidate:
  raise `stop_error('EVIDENCE_MISMATCH', 'task source moved after staging', ...)`.
- `abort_owned` accepts, as an owned merge target, `MERGE_HEAD == staged.task_commit`
  when `staged.task_commit` is an ancestor of the worker HEAD (`git merge-base
  --is-ancestor`) and the staged branch and project match. Every other check of
  `abort_owned` stays, in particular the refusal of foreign changes in the primary
  checkout and of a main that moved from the lease's `main_commit`.
- In `run_integration_step`, an `EVIDENCE_MISMATCH` raised by `verified_candidate` calls
  `strategy.reconcile_landing(task_id, root)` (the engine's owned abort) and returns
  `None`, so the same `cardine run` goes on to the worktree and validation steps: the
  moved branch is delivered again (task 204), validated (a reused validation passes at
  once, task 201), and staged again. If the reversal refuses, the stop is
  `INTEGRITY_MISMATCH` and its detail names both the staging refusal and the abort
  refusal, in the format of part 2. Nothing else is reversed: no `git reset` of the task
  branch, no change in the primary checkout beyond what `abort_owned` already does.

### 2. One message format for developer stops

Add `refusal(what, expected, found, why, resolve)` to `src/cardine/stops/render.py`. It
returns

```text
<what> | expected <expected> | found <found> | <why> | resolve: <resolve>
```

with commits and digests shortened to 12 characters by the caller. Use it for the stops
this task adds or changes (`INTEGRITY_MISMATCH`). Do not
rewrite other messages.

### 3. The stop names the step that raised it

`diagnostic_result` defaults to `step="contract"`, and `dispatch_run` never passes
another, so a stop raised while staging reports step `contract`. `dispatch_run` keeps the
stage it is in (`contract`, `candidate` for `run_integration_step`, `worktree` for
`run_worktree_step`, `validation` for `run_validation_step`) and passes it to both
`diagnostic_result` calls.

### Registry

Add one entry to `capabilities/stop-codes-v1.json`, `resolution: guardrail`,
`human_decision: true`, `kind: stop`, with a `test` naming the test that raises it:

- `INTEGRITY_MISMATCH`: a lease, staged file or merge target that the task does not own,
  or a reversal the engine cannot prove safe. Resume: `cardine run {task_id} --project
  {project}` after the developer resolved the difference named in the detail.

`COMMAND_REFUSED` stays the fallback for every refusal nobody classified.

**Revision 2 (2026-11-08).** The redelivery that part 1 relies on stops in
`verify_delivery` (`src/cardine/lifecycle/delivery.py`): the check of the state recorded
in the delivery commit compares its artifacts with the working tree, and a second
delivery has rewritten `.cardine/evidence/<ID>.json`, so the run stops with `changed or
missing receipt artifact`. The check becomes
`receipts.verify_receipts(root, recorded, portable=True, artifact_ref=commit,
context=context)`, which compares the artifacts with their content at that commit. Use
`artifacts=False` only if a covered artifact is not tracked at that commit, and say so in
the handoff. The new registry code also needs its baseline entry in
`tests/test_command_word.py`. `test_integrate_stage_reports_primary_dirty_through_the_registry`
in `tests/test_worktree_lifecycle.py` is stale since task 202, because an untracked file
no longer makes the primary checkout dirty: it modifies a tracked file instead and keeps
the expected message.

No prototype was made, by developer decision. The cause of part 1 is the joined check
quoted above; the reversal reuses the existing owned abort.
