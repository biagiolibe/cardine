## Objective

`cardine init` requires seven flags. One of them, `--validation`, is a JSON file whose
`REUSE`/`BOUNDED`/`FULL` lists are an internal concept. `cardine adopt` needs the same
inputs. Most projects need only a name and one test command. This task gives every choice
a visible default and lets a single `--test` flag, or detection, replace the JSON file.
It is proposal P2 of `docs/ONBOARDING_DESIGN.md`, accepted on 2026-11-11.

### 1. `--test`

`init` and `adopt` accept `--test "<command>"`. It cannot be combined with
`--validation`. It produces this validation declaration:

```json
{"commands": {"test": "<command>"}, "baseline": ["test"],
 "candidate": {"REUSE": [], "BOUNDED": ["test"], "FULL": ["test"]}}
```

`--validation <file>` keeps its current meaning.

### 2. Detection

With neither `--test` nor `--validation`, Cardine reads the project root and takes the
first match, in this order:

| Source | Condition | Command |
| --- | --- | --- |
| `Makefile` | has a `test:` target | `make test` |
| `package.json` | `scripts.test` exists and is not the npm placeholder that starts with `echo "Error: no test specified"` | `npm test` |
| `pyproject.toml`, `pytest.ini`, `setup.cfg`, `tox.ini`, `conftest.py` | pytest configuration: a `[tool.pytest.ini_options]` table, a `pytest.ini`, a `[tool:pytest]` section, a `[pytest]` section, or a `conftest.py` | `python3 -m pytest` |
| Python files | a `tests/` directory or a `test_*.py` file at the root | `python3 -m unittest` |

Detection only reads files. It runs no command and executes no project code. When nothing
matches, `validation` stays a missing input: `--check` reports it with the hint `pass
--test "<command>"`, and `--apply` refuses, as today.

### 3. Defaults for the other choices

| Choice | Default |
| --- | --- |
| `--name` | the project directory name |
| `--slug` | the name, lowercased, with each run of characters outside `a-z0-9` replaced by `-` and leading or trailing `-` removed |
| `--preset` | `lean` |
| `--language` | `English` |
| `--task-identity` | `opaque` |

For `adopt` on an existing installation, a value that the installation provides keeps
precedence over a default. An explicit flag always wins.

### 4. Show where each value came from

- `init --check` and `init --apply` print one line per choice:
  `choice: <name> = <value> (<source>)`. The source is `flag`, `default`, `detected from
  <file>`, or `installation`.
- `adopt` adds a `choices` object to its JSON plan, with the same fields: `{"<name>":
  {"value": ..., "source": ...}}`.
- The plan digest binds the resolved values, so `--apply` uses exactly what the preview
  showed.

### 5. Guidance and skill

- In `src/cardine/shared/project_guide.py`, the bootstrap section no longer asks for a
  JSON file. It says that every choice has a default shown in the preview, and that
  `--test "<command>"` sets the test command when detection finds none.
- In `skills/cardine-project/SKILL.md`, the init and adopt bullets no longer say «Never
  choose them by default». They say: run the preview, show the developer every choice with
  its source, ask them to confirm or change it, then apply with the confirmed values as
  explicit flags.
- `docs/ADOPT_COMMANDS.md` shows the short form:
  `cardine adopt --project . --check --test "python3 -m unittest"`.
- `docs/PUBLIC_SURFACE.md` lists `--test` and the `choices` plan field.

- [ ] Each row of the detection table and the npm placeholder have a unit test, and so
  does the case where nothing is detected.
- [ ] `--test` together with `--validation` is refused with a usage error.
