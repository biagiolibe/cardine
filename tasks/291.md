## Objective

`docs/ADR_PRODUCT_DIRECTION.md`, decision 1, positions Cardine as the gate between an
agent's change and `main`. Cardine works with the developer's spec tool instead of
replacing it. The README is behind the product and does not say this:

- "How a task lands" lists seven steps with review before any CI. Since task 278, CI on
  the delivered head comes before review when `ciBeforeLanding` is set. Since task 282,
  `cardine run` can launch a read-only reviewer.
- Nothing tells a reader who uses Spec Kit, Kiro or BMAD how Cardine fits.
- Nothing says when not to use Cardine, or how a small task skips review and CI.

### 1. Opening

Below the tagline, keep the existing two paragraphs. Add this sentence after the quote
"Specs say what to build…": "Use it with the spec tool you already have."

### 2. "How a task lands"

Update the steps:
- after Validation, a CI step that applies with `ciBeforeLanding`: the required checks
  pass on the delivered head before review;
- Review names its sources: a reviewer that `cardine run` launches with no write
  capability, or the developer's own verdict.

Keep seven or eight steps and the outcome table. Remove the paragraph that says CI comes
"before landing", which the new step replaces.

### 3. New section "Works with your spec tool", after "What Cardine does"

At most 120 words. Spec Kit, Kiro and BMAD turn an idea into requirements, a plan and
tasks. Cardine takes one task at a time and lands it with measured validation, CI,
independent review and integration. Write the tasks there, and register each one with
`cardine task new`. An import is planned (`docs/ADR_PRODUCT_DIRECTION.md`, work item 6).

Then a table, one row per tool:
- columns: "Structures", "Enforced by", "Lands on main";
- rows: Spec Kit, Kiro, Superpowers, Agent OS, Cardine;
- claims stay at the category level, for example "spec, plan, tasks" and "convention
  in prompts";
- each tool name links to its official page;
- no star counts and no version numbers.

### 4. New section "When not to use Cardine", before "What Cardine is not"

Three bullets:
- exploration and throwaway prototypes;
- a repository without a test command;
- work that cannot be split into tasks of about ten files.

Then one sentence on the quick path. A task record can set
`Options: {"review": "not_required", "ciBeforeLanding": false}` for a small change. Link
`docs/PROJECT_DECLARATION.md`.

### 5. "What Cardine is not"

Update the bullet "Not yet for team workflows": pull request approvals as a review source
are planned (`docs/ADR_REVIEW_VERDICT_SOURCES.md`). Landing through pull requests remains
planned.
