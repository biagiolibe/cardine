## Objective

Codex asks for permission on every `cardine run`. The block of user rules that `cardine
setup` installs in `~/.codex/rules/cardine.rules` (`CODEX_USER_RULES` in
`src/cardine/hosts/codex.py`) was written before `cardine run` existed. Its allow list has
`execution`, `task`, `review` and others, but neither `run` nor `status`, and those are the
two commands an implementer calls most. Its own comment says it covers the "read-only and
task-lifecycle commands".

Add `"run"` and `"status"` to the list of the `cardine` allow rule. `cancel` and `abort`
stay out: they need the developer's terminal.

The block must also reach installations that already have it. `plan_codex_user_rules`
raises `has changed` for any block different from `CODEX_USER_RULES`, so changing the
constant would make `setup` refuse on every machine that has the old one. And
`LEGACY_CODEX_USER_RULES` must stay byte-identical, because the migration of the legacy
block matches its exact bytes. So:

- `PREVIOUS_CODEX_USER_RULES = LEGACY_CODEX_USER_RULES.replace('# MERIDIAN:', '# CARDINE:')`
  keeps the current block;
- `CODEX_USER_RULES` is the same text with the marker `codex-user-rules v2` and the two
  new words;
- in `plan_codex_user_rules`, a block equal to `PREVIOUS_CODEX_USER_RULES` gets the new
  block as `proposed`, in place and with the bytes around it unchanged, and status `stale`,
  which `cardine codex doctor` already reports. Any other different block keeps refusing.
