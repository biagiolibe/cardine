# Task 250 — Suggest cross-cutting tests when planning a task

> **ID**: `250`
> **Category**: Feature
> **Priority**: 🟠 P2
> **Estimate**: ~2h
> **Assigned to**: unassigned
> **Session**: Delivery workflow, 2026-11-11
> **Origin**: Late CI failures on tasks 246–248

## Objective

1. Add a read-only repository helper, `python3 scripts/suggest_task_tests.py --record <draft>`,
   that reads a draft task's Expected code surface before `cardine task new`.
   Reuse the existing surface parser and path matching semantics. Match the planned
   paths against a small, documented set of repository-specific relationships between
   files and cross-cutting tests. For every suggestion, name the module, the matching
   path or pattern, and the behavior it protects. Output a deduplicated, stable
   list and a ready-to-copy fragment with one `--module` per suggestion.
2. Add a planning step to `tasks/TASK_BLUEPRINT.md` before task registration. Run the
   helper, add applicable suggestions to the existing `task-tests` command alongside
   feature tests and standard guards, and review any uncovered area using repository
   search. When a suggestion is excluded, record the reason in Technical Context.
   Keep full-suite validation in CI.

## Acceptance Criteria

- [ ] A draft can be outside the repository and can name planned files that
  do not yet exist. The helper handles exact paths and bounded surface globs,
  deduplicates modules, and explains why each was selected.
- [ ] The initial rules cover the observed gaps. Project skill changes suggest
  `test_template_commands`. Changes to test modules suggest `test_run_tests`
  for the parallel isolation guard. Changes to task-status and lifecycle startup
  paths affected by task 246 suggest `test_command_context` and
  `test_execution_start_fresh_task` as applicable. Verify these cases using
  proposed surfaces based on tasks 246–248.
- [ ] The helper reports unmatched paths as uncovered by its rules. An empty or
  invalid surface gets an actionable diagnostic. Tests detect stale module
  names in the rule set. Suggestions do not import, discover, or execute tests
  or modify the draft or repository.
- [ ] The blueprint shows an example of moving the suggested module flags into
  the frozen Validation command before registration. The resulting command
  uses the existing test runner and can run only the selected modules locally.
- [ ] The affected validation modules and repository checks pass. The lifecycle
  records validation using the ordinary task evidence flow.
