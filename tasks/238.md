## Objective

`cardine init` writes `PROJECT_PLAN.md` and `TECH_DESIGN.md` from `templates/single/`, and
`cardine adopt` adds a status region to a project's plan. Nothing reads either file: no
router, workflow file, or command names them, and after task 237 the status view is the queue
alone. The developer removed the empty `TECH_DESIGN.md` by hand from both converted projects.

After this task `init` and `adopt` create neither file, and an existing `PROJECT_PLAN.md` is
the project's own file, left as it is.

- Delete `templates/single/PROJECT_PLAN.md` and `templates/single/TECH_DESIGN.md`.
- `src/cardine/templates/init.py`: remove the `PROJECT_PLAN.md` line that calls
  `splice_region`, and import only `input_digest` and `render_queue`.
- `src/cardine/adopt/plan.py`: in `keep_project_files`, remove the `PROJECT_PLAN.md` branch and
  the `REGION_BEGIN`/`REGION_END` import; an existing plan is then an ordinary existing file
  that adoption keeps. Update the docstring.
- `src/cardine/adopt/apply.py`: `_views(root)` renders only the queue, with
  `input_digest(root, inputs, {_target(root, queue)})`; remove the plan path from the paths
  recorded in `before`, and stop writing and reading `payload['original_plan']`.
- `src/cardine/tasks/status_render.py`: delete `REGION_BEGIN`, `REGION_END`, `DEFAULT_PLAN`,
  `PLAN_STUB`, `render_plan_region`, and `splice_region`, and the docstring sentence about
  them.
