# Task 244 — Make the console faster to open and easier to scan

> **ID**: `244`
> **Category**: Fix
> **Priority**: 🟠 P2
> **Estimate**: ~3h
> **Assigned to**: unassigned
> **Session**: Console follow-ups, 2026-11-10
> **Origin**: friction

## Objective

Show a useful task list promptly at launch and let maintainers see where
work stands and what to do next, even in a terminal that occupies half
the screen. Keep the complete task record accessible on demand.

## Acceptance Criteria

- [ ] Measure time to the first usable task list against the post-241
  baseline with the same checkout or representative fixture and terminal
  width. Record the method and before and after measurements. Address
  remaining startup cost where the measurement warrants it. A slow
  per-task detail or lifecycle probe must not delay the initial list.
  If information loads later, distinguish pending data from confirmed
  state and update the row when it arrives.
- [ ] Keep one task list with search. Remove the per-state tabs and
  their controls. Tasks that need attention, including genuine pending
  cleanup, remain visible in the list with their status or diagnostic.
  Preserve the read-only historical cleanup behavior from task 241.
- [ ] Add Elapsed and Gate columns to the task list. At 80 terminal
  columns, task ID, a recognizable title, elapsed time, and current gate
  fit without the right panel. Truncate the title first and keep its full
  text in the Enter view. Elapsed uses the existing task start time and
  is blank for tasks that have not started. Gate uses concise labels
  such as Validation, Waiting for CI, or Cleanup, based on actual run facts.
- [ ] The right panel shows the next action near the top, with existing
  copy and launch controls where applicable. It also shows elapsed time,
  the current phase, and applicable remaining Cardine run gates in plain
  language. Explain a wait or stop with the available facts, such as the
  required CI check before landing. Keep a short objective in the panel.
  Acceptance criteria and full technical details are available in the
  view opened with Enter.
- [ ] Remove the routine refreshed-now label. Show a refresh warning when
  an update failed and the last successful view is stale. Preserve task
  selection, search, and keyboard access across refreshes and terminal
  resizes.
- [ ] Verify a narrow and a wide terminal, a running task, a real pending
  cleanup, and a refresh failure. Add focused regression coverage for the
  list layout, detail view, and any deferred loading behavior.
