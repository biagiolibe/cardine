## Objective

When this repository redid its switch on a new `main`, `cardine adopt --apply` stopped
twice before writing anything, and the developer had to move two files by hand:

```text
"diagnostics": ["completed adoption output changed: .cardine/baselines/1.4.0/.codex/hooks.json"]
"diagnostics": ["adoption conflicts with existing receipt authority"]
```

1. **The completed receipt has no commit.** `_binding` in `src/cardine/adopt/apply.py`
   binds the adoption receipt in the temporary directory to the project path and the
   plan digest only. The plan was byte-identical on the new commit, so `apply_adopt`
   took the earlier, completed adoption for a replay and checked that its outputs were
   still on disk. They were not: the tree was clean. Bind the receipt to `HEAD` as well,
   so that the same plan on another commit starts a new adoption. On the same commit a
   completed adoption still refuses changed or missing outputs.
2. **The earlier local authority is residue.** The first apply wrote the ignored
   `.cardine/receipt-authority.json`. It survived the branch switch, and adoption
   refused to replace it. Adoption already requires an empty task state store before it
   declares its writes, so no state depends on that file. Replace it with the observed
   authority instead of refusing.

## Technical Context

- `pending` in `src/cardine/lifecycle/file_operation.py` returns no intent for a
  completed receipt, so a completed receipt with another owner is simply superseded;
  an unfinished one with another owner is still refused.
- The earlier authority is replaced through `receipts.authorize_project` without
  `new=True`; the empty store, checked when the adoption is declared, is what makes
  the file residue.
- The prototype base already contains task 189, which also edits
  `src/cardine/adopt/apply.py`.
- During development, run only what the change touches: `python3
  scripts/run_tests.py --parallel --module <name>`, repeating `--module`. Do not run
  `python3 -m unittest` directly. Run the full suite once, as the counted
  clean-clone validation.
- Run validation suites one at a time and redirect each one's output to a log file
  with its exit code appended, so the result survives a lost process handle.
- Other tasks share this machine. Stop only your own processes, by process ID;
  never `pkill` test runs by pattern.
