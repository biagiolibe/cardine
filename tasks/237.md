## Objective

`cardine status --write`, and every integration through `_regenerate_status_views` in
`src/cardine/integration/merge.py`, write two views of the same snapshot: the queue file and
a region between `<!-- cardine-status:begin -->` and `<!-- cardine-status:end -->` in
`PROJECT_PLAN.md`. Nothing reads the plan region. No router, workflow file, or command names
it, and the queue already shows every open task with its totals. A plan file that lacks the
region makes every integration report `STALE`, and a missing plan file is created.

After this task the queue is the only generated view. `write_views` and `stale_views` read
and write the queue alone; a plan file, with or without a region, is never read, written,
created, or staged.

This task does not touch `init` or `adopt`: they still import `render_plan_region`,
`splice_region`, `REGION_BEGIN`, `REGION_END`, and `PLAN_STUB`, so those stay in
`status_render.py`. Task 238 removes them.

In `src/cardine/tasks/status_render.py`:

- Replace `_view_paths` with `_queue_path(root, config) -> Path`, which resolves only
  `locations.queue` (default `DEFAULT_QUEUE`) and keeps the `view path escapes the project`
  check.
- `_render_views` returns `(queue, new_queue_bytes, old_queue_bytes)`, with `input_digest(root,
  inputs, {queue})`.
- `stale_views` returns `[queue]` when the rendered bytes differ, else `[]`.
- `write_views` builds `changed` from the queue alone; the staging, replacement, and restore
  code stays as it is.
- The module docstring says the generated view is the queue, and that the plan-region helpers
  remain only for `init` and `adopt`.

In `src/cardine/integration/merge.py`, the `_regenerate_status_views` docstring says "the
queue view" instead of "the queue and plan views".
